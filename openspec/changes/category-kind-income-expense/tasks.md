## 1. База и модель

- [x] 1.1 `WalletContract.AccountEntry.COLUMN_CATEGORY_KIND`, колонка в `accountTableBody()` (`INT NOT NULL DEFAULT 2`), `DATABASE_VERSION = 92`, шаг `v92` в `onUpgrade` по образцу v76: `ALTER TABLE … ADD COLUMN`, только если колонки ещё нет; строки не помечаются `dirty`. Проверка: Robolectric-тест миграции v91 → v92 — колонка есть, у всех строк `2`, `dirty` не изменился; апгрейд со старой базы (v70), где колонка уже создана `accountTableBody()`, не падает на `duplicate column`.
- [x] 1.2 `AccountItem.CategoryKind` (`EXPENSE(0)`, `INCOME(1)`, `BOTH(2)`) с безопасным `fromValue` (любое незнакомое значение — `BOTH`, как `SystemKind.fromValue`), поле и геттер в `AccountItem`, чтение колонки в `WalletDbLoader.LoadAccounts`. Проверка: юнит-тест `fromValue(-1)`, `fromValue(3)` → `BOTH`; тест загрузки счёта с видом `1`.
- [x] 1.3 `WalletDbCRUD.InsertAccount` и `UpdateAccount` принимают вид и пишут колонку, помечая строку `dirty = 1`; пути создания кошелька и системных категорий оставляют `2`. Проверка: тест записи — категория с видом `1` читается обратно, кошелёк и «Transfer» остаются `2`.
