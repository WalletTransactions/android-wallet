# Proposal: базовая спецификация android-wallet

## Why

OpenSpec появился в android-wallet 2026-10-24, и с тех пор спецификации
`openspec/specs/` наполнялись только архивами изменений: ИИ, импорт выписки,
синк, иконки, капитальные активы, справочник валют. Основа приложения —
ввод операций, лента, кошельки, отчёты, повторяющиеся операции, курсы,
блокировка, импорт и экспорт, вход на сервер — описана только кодом,
README и `docs/ARCHITECTURE.md`. Поэтому изменения в этих местах нельзя
оформить дельтой: нет спецификации, которую дельта меняет. Нужно
зафиксировать текущее поведение как базу — без изменения кода.

## What Changes

- Восстанавливается спецификация **текущего** поведения приложения по коду
  (`app/src/main`, коммит `316bfc7`), ресурсам `res/values-ru/` (тексты
  интерфейса — дословно), юнит-тестам `app/src/test` и `docs/ARCHITECTURE.md`.
- Описываются только области без спецификации. Где спецификация уже есть, но
  покрывает один срез (`account-screens`, `currency-pairs`, `data-export`),
  добавляются требования (`## ADDED Requirements`) к ней же, без правки
  существующих.
- Сервисы (wallet-api, google-auth, wallet-ai, источники курсов) описываются
  как внешние границы: что вызывает приложение и как трактует ответ. Их
  контракты остаются в их репозиториях.
- Расхождения документации и кода и неожиданное поведение фиксируются в
  `design.md` как наблюдения; требованиями они не становятся и здесь не
  исправляются.
- Код, схема базы и поведение приложения **не меняются**.
- Не входит в базу то, что ведут открытые changes: `android-flavors`
  (варианты prod/qa), `archive-wallet-writeoff` (списание остатка при
  архивации), `new-user-default-set` (встроенный набор, подключение к
  кошельку).

## Capabilities

### New Capabilities

- `operation-entry`: окно «Новая операция» / «Изменение операции» — расход,
  доход, перевод, валютный перевод с курсом и комиссией, дата, комментарий,
  проверки, удаление, выбор счёта.
- `operations-feed`: таб «Операции» — лента по дням, итог дня, строки по виду
  операции, плитки и фильтр по счетам, переход к правке.
- `period-summary`: общая шапка корневых табов — период, валюта эквивалента,
  карточка денег за период, строка фильтра, нижняя панель, сохранение
  состояния.
- `balances-and-equivalent`: расчёт баланса кошелька, курс на дату, пересчёт
  в эквивалент и пометки «≈» / «~», точность сумм и курсов.
- `reports`: таб «Отчёт» — доходы и расходы по категориям за период.
- `wallets-tab`: таб «Кошельки» — список кошельков с остатком, изменением за
  период и эквивалентом, сортировка.
- `recurring-operations`: правила повторяющихся операций и их проведение.
- `reminders`: напоминания пользователю.
- `currency-rates`: история курса пары, ручной ввод, график, загрузка из
  внешних источников.
- `icon-library`: свои иконки — группы, добавление из галереи, кадрирование,
  правка, удаление, выбор.
- `data-import`: импорт базы из файла.
- `data-reset`: очистка данных на телефоне.
- `app-lock`: блокировка приложения PIN-кодом и биометрией.
- `server-account`: адрес сервера, вход через Google, токены, ручной и фоновый
  синк, журнал синка.
- `telegram-link`: подключение Telegram-бота с телефона.
- `sync-notifications`: уведомления об операциях с других устройств.
- `sync-data-exchange`: правила обмена строками с wallet-api — состав и
  порядок отправки, применение загруженного, отложенные строки, конфликты имён.
- `more-and-settings`: таб «Ещё» и экран «Настройки».

### Modified Capabilities

- `account-screens`: ADDED — справочник «Кошельки и категории»: создание,
  правка, архив, удаление, уникальность имён, системные категории.
- `currency-pairs`: ADDED — список пар, создание и правка пары.
- `data-export`: ADDED — формат и содержимое экспорта, сообщения об исходе.

Существующие требования этих спецификаций не меняются.

## Impact

- Код: не меняется. Затрагивается только `openspec/` этого репозитория.
- После архивации в `openspec/specs/` появятся 18 новых спецификаций, три
  существующие пополнятся. `docs/ARCHITECTURE.md` остаётся описанием
  устройства; поведение — в спецификациях.
- Открытые changes (`android-flavors`, `archive-wallet-writeoff`,
  `new-user-default-set`) не пересекаются с базой и архивируются независимо.
- Последующие изменения (исправление наблюдений, новые функции) оформляются
  отдельными changes с дельтами к этой базе.
