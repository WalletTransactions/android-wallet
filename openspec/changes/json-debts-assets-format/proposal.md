# Proposal

## Why

Файловый JSON-обмен (`data-export` / `data-import`) отстал от приложения: он не
знает ни контрагентов и долговых кошельков (change `debts`), ни капитальных
активов (`capital-assets`) и их системной категории «Переоценка». Экспорт молча
теряет эти данные, а импорт превращает долг в обычный кошелёк — без контрагента,
вне экрана «Долги». Конвертер Money Lover (`tools/moneylover`) уже умеет
находить долги и возвраты и пишет в `trans.json` долговые кошельки, но передать
контрагента в приложение нечем.

## What Changes

- Формат JSON получает раздел `counterparties` и два необязательных блока у
  кошелька в `accounts`: `debt` (контрагент, срок, комментарий) и `asset` (тип,
  «входит в капитал», комментарий). Категория «Переоценка» помечается
  `"system": "revaluation"`.
- Экспорт пишет эти данные; импорт их читает и применяет раньше счетов
  (контрагенты → счета → пары → курсы → операции).
- Файл без новых полей импортируется как раньше (раздел и блоки необязательны).
- Конвертер `tools/moneylover` заполняет `counterparties` и блок `debt` у
  долговых кошельков; обновляются README конвертера (раздел про долги) и
  описание формата (`_comment` экспорта, диалог «Формат», `schema/`).

**Не входит:** привязка к контактам телефона (`counterparty_contact` —
локальная, не экспортируется); архивные кошельки; суммы переоценок отдельным
разделом (это обычные операции через категорию «Переоценка»); CSV-импорт.

## Capabilities

### New Capabilities
Нет.

### Modified Capabilities
- `data-export`: содержимое JSON-экспорта — контрагенты, блоки `debt`/`asset`,
  метка системной категории переоценки.
- `data-import`: формат JSON и порядок применения разделов — чтение тех же
  полей, их проверки и пропуск некорректных элементов.

## Impact

- `Data/WalletExportData.java`, `Data/WalletImportData.java`, при необходимости
  `Data/WalletDbCRUD.java`/`WalletDbLoader.java` (поиск контрагента по имени,
  пометка кошелька долговым/активом по образцу экранов).
- Строки «Формат» импорта (`strings_import.xml`, ru/en), `schema/`, README.
- `tools/moneylover`: `debts.py`, `main.py`, `csv_export.py`, `README.md`.
- Серверу и синку ничего не меняется: импорт пишет в те же таблицы
  `counterparty`/`account_debt`/`account_asset` с `dirty`, дальше их разносит
  обычный синк.
