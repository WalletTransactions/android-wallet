## MODIFIED Requirements

### Requirement: Формат JSON
Файл JSON SHALL быть объектом с необязательными массивами `counterparties`,
`accounts`, `currency_pairs`, `rates`, `operations` либо (старый формат)
массивом одних операций. Разделы SHALL применяться в порядке контрагенты →
счета → пары → курсы → операции независимо от порядка ключей в файле.
Элемент `counterparties` — `name`, необязательные `comment` (по умолчанию
пусто), `icon` (по умолчанию `unknown`), `archived` (по умолчанию `false`);
контрагент с тем же именем среди живых (по правилу уникальности имён
контрагента) обновляется, а не дублируется. Элемент `accounts` — `name`,
необязательные `comment` (по умолчанию имя), `icon` (по умолчанию
`unknown`), `currency` (`iso`, необязательные `name` — по умолчанию код,
`icon`), `debt`, `asset`, `system`, с той же обработкой, что строка CSV
счетов. Элемент `currency_pairs` — `symbol`, `base`, `quote` (коды валют);
пара с занятым `symbol` не заводится повторно. Элемент `rates` — `symbol`,
`date`, `rate`; курс для несуществующей пары SHALL пропускаться с причиной
«<symbol> <дата> — нет валютной пары с symbol=<symbol>». Элемент с
недостающим обязательным полем SHALL пропускаться с причиной «<раздел>#<номер>
— <ошибка>» (для операций «#<номер> — <ошибка>»). Итог — «Импортировано N
элементов» по всем разделам.

#### Scenario: Счёт, пара и курс одним файлом
- **WHEN** импортирован JSON с кошельком в USD, парой `EURUSD` (`EUR`/`USD`) и курсом `EURUSD` на 2020-08-20
- **THEN** кошелёк, пара и курс заведены, итог «Импортировано 3 элемента»

#### Scenario: Старый формат
- **WHEN** импортирован JSON — голый массив операций
- **THEN** он читается как раздел `operations`

#### Scenario: Файл без новых полей
- **WHEN** импортирован JSON, в котором нет `counterparties` и блоков `debt`/`asset`/`system`
- **THEN** он импортируется как раньше, долгов и активов не появляется

## ADDED Requirements

### Requirement: Долги и активы в JSON
Блок `debt` (`counterparty` — обязательное имя, `comment`, `due_date` в
`yyyy-MM-dd`) у кошелька SHALL делать его долговым: контрагент ищется среди
живых по имени (правило уникальности имён контрагента) и, если его нет —
заводится; создаётся или оживляется строка долга кошелька с комментарием и
сроком. Блок `asset` (`type`: `real_estate`, `vehicle` или `other`;
`include_in_net_worth`, по умолчанию `true`; `comment`) SHALL делать кошелёк
капитальным активом. Кошелёк не может быть одновременно долговым и активом:
элемент с обоими блоками, блок на категории (без `currency`), блок на уже
противоположном по признаку кошельке, неизвестный `type` или неверная
`due_date` SHALL пропускаться с причиной «accounts#<номер> — <ошибка>», при
этом остальные элементы файла применяются. `"system": "revaluation"` у
категории SHALL делать её системной категорией переоценки; если такая уже
есть на телефоне, вторая не заводится. Записанные признаки SHALL уходить на
сервер обычным синком.

#### Scenario: Долговой кошелёк с новым контрагентом
- **WHEN** импортирован кошелёк «Вася · USD» с `"debt": {"counterparty": "Вася", "due_date": "2026-12-31"}`, а контрагента «Вася» на телефоне нет
- **THEN** заведены контрагент «Вася» и долговой кошелёк «Вася · USD» со сроком 2026-12-31; он виден на экране «Долги»

#### Scenario: Существующий контрагент
- **WHEN** в файле контрагент «вася», а на телефоне уже есть «Вася»
- **THEN** второй контрагент не заведён, кошелёк привязан к «Васе»

#### Scenario: Актив
- **WHEN** импортирован кошелёк «Квартира» с `"asset": {"type": "real_estate", "include_in_net_worth": true}`
- **THEN** «Квартира» — актив-недвижимость, входящий в капитал

#### Scenario: Долг и актив одновременно
- **WHEN** у одного кошелька в файле есть и `debt`, и `asset`
- **THEN** элемент пропущен с причиной «accounts#<номер> — …», остальные элементы импортированы

#### Scenario: Переоценка
- **WHEN** импортирована категория `{"name": "Переоценка", "system": "revaluation"}`, а на телефоне уже есть системная категория переоценки
- **THEN** вторая категория не заведена
