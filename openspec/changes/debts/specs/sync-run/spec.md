# Spec Delta

## ADDED Requirements

### Requirement: Повторная загрузка и отправка после появления таблиц контрагентов и долгов
После обновления приложения до версии, вводящей синхронизируемые таблицы
`counterparty` и `account_debt`, первый успешный синк SHALL один раз
перечитать поток ledger с начала (курсор ledger сбрасывается, прочие потоки
и `ledger_id` не затрагиваются) и однократно пометить все живые строки
`counterparty` и `account_debt` как требующие отправки. Дальше работает
обычное постраничное сохранение курсора: обрыв продолжает с последней
страницы.

#### Scenario: Обновление приложения
- **WHEN** приложение обновилось до версии с таблицами долгов и выполняется первый синк
- **THEN** pull ledger идёт с курсора 0, курсор reference не меняется, флаг однократного перечита снимается

#### Scenario: Обрыв перечита
- **WHEN** перечитывание оборвалось на середине
- **THEN** следующий синк продолжает с последней сохранённой страницы, а не с нуля

#### Scenario: Строки, созданные до выката сервера
- **WHEN** на устройстве есть строки `counterparty` и `account_debt`, созданные в версии, которую сервер ещё не принимал
- **THEN** при первом синке после обновления они отправляются повторно
