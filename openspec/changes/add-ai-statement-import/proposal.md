# Proposal

## Why

Выписку банк отдаёт на телефон («Поделиться» PDF/CSV), а разобрать её сейчас
негде: импорт выписки в wallet-ai готов (`add-statement-import`), но клиента у
него нет — веб ещё не начат. Вносить операции по выписке руками долго, а
повторная загрузка без проверки задваивает траты.

## What Changes

- **Экран «Выписка»** (вход с экрана «ИИ» и через «Поделиться» файлом из
  банковского приложения): выбор кошелька, загрузка файла в
  `POST /api/ai/imports`, ожидание разбора с прогрессом — только пока экран
  открыт. Незавершённый импорт находится заново после возврата на экран.
- **Список разобранных строк** с сервера: сумма, дата, продавец, предложенная
  категория, состояние строки («добавлена», «ждёт», «нужна категория»,
  «проверить», «похоже, уже есть», «не для записи»).
- **Правка в стандартном окне операции**: тап по строке открывает «Новая
  операция» с полями строки. Окно сохраняет операцию с заданным uuid
  (`uuid = row_id` строки), а если она уже есть — открывает её на правку.
  После «Сохранить» строка помечается добавленной, сервер получает выбранную
  категорию (учится правилу продавца) и отметку о записи.
- **«Записать готовые»** — одной кнопкой строки без вопросов: категория
  выбрана, кошелёк и категория есть на телефоне, похожей операции нет.
- **Проверка на дубли на телефоне** по полям: тот же кошелёк, та же сумма,
  дата ±1 день, один к одному. Серверные группы дублей приложение не
  использует: задача ИИ — разобрать и предложить категории.
- **Один uuid — одна операция**: проверка перед вставкой и уникальный индекс
  `operation(uuid)` в локальной базе (миграция v82).
- Записываются **только расходы**; доходы и переводы видны как «не для
  записи».

Вне охвата: доходы и переводы (ждут `add-statement-transfers` в wallet-ai),
уведомление о завершении разбора, вставка текста выписки, свои форматы и
правила импорта (веб).

## Capabilities

### New Capabilities
- `ai-statement-import`: экран «Выписка» — загрузка файла, ожидание разбора,
  список строк и их состояния, правка через окно операции, «Записать
  готовые», отметка записанного на сервере, проверка на дубли по полям.
- `operation-identity`: операция с заданным заранее uuid — окно операции
  создаёт её с этим uuid или открывает существующую на правку; на телефоне не
  больше одной операции на uuid.

## Impact

- Код: новый экран `Activities/StatementImportActivity` (+ layout), разметка
  и вход на экране «ИИ» (`AiActivity`); `AiApiClient` — методы
  `/api/ai/imports*`; `ai/` — модель импорта и проверка на дубли;
  `TransactionActivity` — extra uuid, «создать или открыть»;
  `WalletDbCRUD.InsertOperation` — вставка с заданным uuid;
  `WalletDbHelper` — миграция v82 (уникальный индекс); `AndroidManifest.xml` —
  приём `ACTION_SEND` с файлом; README и `docs/ARCHITECTURE.md`.
- Серверы: правок нет. wallet-ai — по текущему контракту `openapi.yaml`
  (`/api/ai/imports`, `PATCH /rows` только `category_uuid`, `POST /committed`).
- Зависимости: новых библиотек нет.
- Нагрузка на GPU: как у импорта в вебе — фоновое задание wallet-ai, интерактивная
  трата текстом его опережает.
