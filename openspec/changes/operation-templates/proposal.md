# Proposal

## Why

Типовые события — снятие наличных с картой и комиссией, зарплата с раскладкой по
кошелькам, платёж по кредиту — каждый раз вводятся вручную: вид, счета, сумма,
переключатель комиссии. Заготовок нет. Правила повторяющихся операций умеют
помнить «откуда, куда, сколько», но только одну проводку, только с фиксированной
суммой и только по расписанию: запустить такое правило вручную нельзя.

Шаблон — это «что создать», расписание — «когда». Сегодня они слиты в одну
сущность. Разделив их, получаем ручной запуск (шаблон без расписания) и
повторяющуюся операцию (шаблон с расписанием) на одной модели, а набор шагов с
комиссией — естественное расширение той же модели.

## What Changes

- Новая сущность **шаблон операций**: заголовок (название, комментарий) + упорядоченный
  список **шагов** + необязательное **расписание**. У шаблона и у каждого шага свой `uuid`.
- Шаг — одна проводка: «откуда → куда», режим суммы и необязательная роль «комиссия к
  шагу N». Режимы суммы: «фикс», «% от суммы», «остаток» (остаток забирает округление).
- **Запуск из списка шаблонов**: вводится общая сумма, показываются разложенные
  проводки, их можно поправить, «Сохранить» создаёт все проводки одной транзакцией.
  Ошибка до записи, если фикс и проценты вместе превышают общую сумму.
- Шаг-комиссия сохраняется отдельной проводкой, связанной с главной шагом
  `operation_link type = 1` — так же, как комиссия за перевод в окне операции.
- Новый экран «Шаблоны операций» в «Ещё»; создание, правка, удаление шаблона и
  кнопка «Сохранить как шаблон» в окне операции.
- **Повторяющиеся операции становятся шаблонами с расписанием.** Расписание —
  отдельная часть шаблона; пустое расписание = ручной шаблон. Генератор по
  расписанию создаёт по шагам шаблона все проводки (с комиссией и связками), а не
  одну. Фиксированная сумма для расписания хранится в шаблоне.
- **Миграция БД**: каждое существующее правило `recurring_operation` превращается в
  шаблон с расписанием и одним шагом «фикс» без потери полей (включая `last_date`,
  `is_active`, дату окончания).
- Первый релиз — только Android, только локальное хранение (как нынешние правила),
  без синка. В форме шаблона основная проводка и необязательная комиссия (только у
  перевода, как в окне операции); модель допускает любое число шагов, форма
  многошаговой правки — следующий change. Все кошельки шаблона — в одной валюте.
- Общая сумма запуска включает все шаги: «остаток» основной проводки = общая сумма
  минус фикс и проценты остальных шагов; проценты считаются от общей суммы.
- Вне объёма (фиксируется в `design.md`): поведение шаблонов и расписаний на втором
  телефоне, общая линковка «шаблон → созданные операции» новым `operation_link.type`,
  разновалютные шаги.

## Capabilities

### New Capabilities
- `operation-templates`: шаблоны операций — заголовок, шаги, режимы суммы, ручной
  запуск с общей суммой, комиссия через `operation_link type = 1`, экран списка и
  форма шаблона, «Сохранить как шаблон» из окна операции, локальное хранение.

### Modified Capabilities
- `recurring-operations`: правило повторяющейся операции становится шаблоном с
  расписанием; список и форма переезжают в «Шаблоны операций»; генератор создаёт
  операции по всем шагам шаблона; миграция существующих правил.
- `more-and-settings`: пункт «Повторяющиеся операции» в «Ещё» заменяется пунктом
  «Шаблоны операций».
- `data-reset`: «Удалить операции и счета» удаляет шаблоны (вместе с шагами и
  расписанием) вместо правил повторяющихся операций.
- `user-guide`: ответ справки о регулярных платежах ведёт на «Ещё» → «Шаблоны
  операций»; добавляется ответ про шаблон с комиссией.

## Impact

- **Android (`android-wallet`)**: `Data/WalletDbHelper` (миграция v93 → v94, новые
  таблицы `operation_template`, `operation_template_step`, перенос и удаление
  `recurring_operation`), `Data/WalletContract`, `Data/RecurringOperationsDb`
  (чтение/запись шаблонов, генератор по шагам), `DataItems/Operations/RecurringOperation`
  (расписание остаётся, шаги отдельно), `Activities/RecurringOperation*Activity` →
  экраны шаблонов, `TransactionActivity` (кнопка «Сохранить как шаблон», запуск с
  подстановкой), `MoreActivity`, строки `strings_recurring.xml` (ru/en).
- **Ссылки на `recurring_operation` по счёту**, которые надо перевести на шаги:
  `SyncEngine` (чистка tombstone), `LedgerConnection` (очистка при смене леджера),
  `ReminderWorker`, `WalletDbCRUD` (перенацеливание правил на актив),
  `ResetDataActivity`, `WalletFillData`.
- **Документация**: `docs/ARCHITECTURE.md` (устройство шаблонов и генератора),
  `schema/table/README.md` (новые таблицы), пользовательская справка раздела
  «Повторяющиеся операции».
- **Другие сервисы**: правок нет. Таблицы шаблонов не синхронизируются: ни
  `wallet-api`, ни `kApplyOrder` / `TABLE_ORDER` не меняются.
- **Совместимость**: обратная совместимость со старыми версиями клиента не
  требуется; миграция одноразовая, без отката на старую схему.
