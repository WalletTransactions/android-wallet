# Design

## Context

Экран «Контрагенты» (`CounterpartiesActivity`) строит список вручную, тап открывает `AlertDialog` с
действиями. Данные контрагента — `CounterpartyItem` (id, uuid, имя, комментарий, `iconUuid`,
архив) из таблицы `counterparty`; ключ контакта лежит отдельно, локально
(`WalletDbCRUD.GetCounterpartyContact` / `SetCounterpartyContact`) и не синхронизируется. Займы
контрагента собирает `DebtsList` в группы по `counterpartyUuid` (`DebtsList.Group` с `totalEq`,
`incomplete`, `approx`). Выбор иконок — `IconPickerActivity`, которая возвращает числовой `_id`, а в
контрагенте иконка хранится как `icon_uuid`. См. proposal.md — зачем.

## Goals / Non-Goals

**Goals:**
- Одна карточка со всем о человеке: иконка, имя, комментарий, контакт, итог и займы.
- Использовать готовые куски (`DebtsList`, `IconPickerActivity`, `ACTION_PICK`), новый код — экран и
  сохранение иконки.

**Non-Goals:**
- История операций контрагента и кнопка-фильтр ленты — вне этого изменения.
- Чтение имени привязанного контакта (нужно `READ_CONTACTS`, спека `debts` его запрещает).
- Любые правки сервера и схемы синка.

## Decisions

1. **Отдельная `CounterpartyCardActivity`, а не диалог.** Карточка нужна для редактирования полей и
   списка займов; диалог на это не рассчитан. Альтернатива — расширить диалог пунктами:
   отвергнута, меню из шести строк хуже, чем нынешние четыре. Раскладка — обычная, а не
   «экран-справочник» (`list-screen-layout`): списка с поиском и кнопкой добавления в ней нет.
2. **Тап по строке открывает карточку сразу.** Диалог действий уходит: «В архив» и «Удалить» переезжают
   в карточку, «Открыть контакт» — в её блок контакта. Решение владельца.
3. **Займы ведут к операциям через карточку займа.** Тап по займу в карточке контрагента открывает
   `AccountItemActivity` долга-кошелька; операции займа открывает её существующая кнопка-фильтр
   (`btnFilterClick` → `presetFilter` по счёту, затем лента). Новой кнопки операций и нового фильтра
   в карточке контрагента нет.
4. **Итог и займы — из `DebtsList`.** Карточка берёт группу своего контрагента, тот же расчёт, что у
   экрана «Долги», поэтому цифры совпадают. В список карточки попадают и архивные займы (с пометкой),
   в итог они входят всегда, как на экране «Долги». Отдельный SQL не нужен.
5. **Иконка: `IconType.CATEGORY`, перевод `_id` → `icon_uuid` при сохранении.** Как у кошелька,
   новый тип иконок не нужен. `IconPickerActivity` отдаёт `_id`; для записи в `counterparty.icon_uuid`
   берётся uuid иконки, при отсутствии иконки — `NULL` и общая заглушка. Альтернатива (новый
   `IconType.COUNTERPARTY`) отвергнута: затрагивает синк иконок и сервер.
6. **Контакт: те же `ACTION_PICK` и локальный ключ.** «Привязать»/«Сменить» запускают системный выбор
   контакта (без разрешения), результат пишет `SetCounterpartyContact`; «Отвязать» удаляет ключ. Имя
   контрагента при перепривязке не меняется. В карточке показывается только «Контакт привязан»,
   потому что имя контакта без `READ_CONTACTS` не прочитать. Если приложения контактов нет, кнопки
   привязки скрыты (как сейчас при создании).
7. **Правка сохраняется при выходе из карточки и по «Назад»; имя проверяется на дубль**
   (`RenameCounterparty`) тем же правилом, что и сейчас: при дубле остаётся прежнее имя и показывается
   «уже есть». Кнопка архива и удаления срабатывают сразу, как в диалоге.
8. **Офлайн.** Всё локально; синк подхватывает изменения как обычную правку `counterparty`
   (`markDataChanged`), как сейчас.

Правка в другом сервисе (google-auth, wallet-api, wallet-ai, wallet-gateway) не нужна: комментарий и
иконка уже входят в синхронизируемые поля `counterparty`.

## Risks / Trade-offs

- [Две иконки в данных: `_id` в форме, `icon_uuid` в базе] → перевод в одном месте
  (`WalletDbCRUD`), юнит-тест на сохранение и на пустую иконку.
- [Карточка раздувает экран «Контрагенты»] → тап открывает её без промежуточного шага, а все
  быстрые действия там же; список остаётся прежним.
- [Список займов дублирует «Долги»] → допустимо: карточка — единственное место, где займы
  видны в разрезе одного человека вместе с его данными.
- [Привязку к контакту нельзя проверить на телефоне без контактов] → пункт ручной проверки.

## Migration Plan

Миграции данных нет: поля уже есть в схеме. Откат — вернуть диалог действий; данные карточки
(комментарий, иконка) остаются в `counterparty`.
