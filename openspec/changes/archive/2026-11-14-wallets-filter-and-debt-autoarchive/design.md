# Design

## Context

Мотивация — в `proposal.md`. Что есть сейчас (по коду и спекам):

- `AccountItem.getIsArchived()` — флаг интерфейса. Выбор счёта при вводе операции
  его уже скрывает (`AccountPickerActivity`, режим не-справочника); таб
  «Кошельки», справочник («режим справочника» того же класса) и отчёты показывают
  архивные наравне с остальными. Итоги флаг не учитывают (спека `wallets-tab`,
  комментарий в `WalletDbLoader`: «Archived wallets are in, deliberately»).
- «Закрытые» на экране «Долги» — вычисляемый переключатель по остатку
  (`DebtsList.group(loans, names, showClosed)`, `Loan.isClosed()`), не флаг.
- Операции пишутся через `WalletDbCRUD.InsertOperation*`, `UpdateOperation`,
  `DeleteOperation` из нескольких мест: `TransactionActivity`, `ForgiveDebt`,
  `RecurringOperationsDb`, `StatementImportActivity`, `WalletImportData`
  (восстановление из файла). Приход с сервера идёт отдельным путём
  (`sync/SyncEngine`) и операций через эти методы не пишет.
- Серверу и контракту синка правка не нужна: `account.is_archived` уже
  синхронизируется (`wallet-api`, `sync-push`). Другие сервисы не меняются.

## Goals / Non-Goals

**Goals:**
- Скрывать архивные по умолчанию там, где пользователь смотрит списки, не
  меняя ни одной цифры в итогах.
- Архивировать погашенный заём автоматически, без авто-разархивирования.
- Поиск и фильтр направления на экране «Долги», поиск в «Контрагентах» и в
  выборе контрагента; чипы секций на «Кошельки».

**Non-Goals:**
- Изменение общего фильтра шапки и экрана «Фильтр».
- Хранение состояния чипов, поиска и переключателей между запусками.
- Правки сервера, `wallet-web`, `wallet-report`.
- Авто-архив для обычных (недолговых) кошельков и активов.

## Decisions

**D1. Один флаг архива для всех списков; «Закрытые» убираются.** Скрытие —
фильтр на этапе построения списка, итоги считаются по полному набору. Для
`DebtsList.group` это значит: `showClosed` заменяется на `showArchived`, а
«закрытый» (нулевой остаток) заём без архива остаётся виден с пометкой
(`debts_closed`). Альтернатива — оставить «Закрытые» рядом с архивом —
отвергнута: два переключателя с почти одним смыслом.

**D2. Авто-архив — явный вызов вокруг записи, а не триггер в `WalletDbCRUD`.**
Поток: пользовательский сценарий снимает остатки затронутых долговых кошельков
до записи, пишет операции, затем сравнивает: был ненулевой, стал нулевой
(`RoundedWalletBalance` с точностью валюты) → ставит `is_archived = 1` той же
записью, что ручная архивация. Всё в той же транзакции, что и операция.
Почему не хук внутри `InsertOperation`: операции одного сценария пишутся
по проводке (перевод с ногой и комиссией, импорт выписки пачкой), и промежуточный
ноль заархивировал бы заём, который в итоге не погашен; а без авто-разархивирования
это не исправить. Альтернатива — проверять «в конце»: она и реализована как
сравнение до/после по набору затронутых кошельков.
Вызывается из: `TransactionActivity` (сохранение, правка, удаление, действия «Дать
в долг» / «Взять в долг» / «Вернуть»), `ForgiveDebt`, `RecurringOperationsDb`,
`StatementImportActivity`. Не вызывается из `WalletImportData` (восстановление
из файла несёт собственные флаги) и из `SyncEngine` (флаг приходит с сервера).
Если сценарий забыт — заём останется неархивным и виден как «закрыт»: ошибка
безопасная, видимая.

**D3. «Нулевой» — переход, а не состояние.** Архив ставится только при
переходе «≠ 0 → 0». Заём, у которого ноль с самого начала (только что
заведённый «Новый заём» до первой выдачи) и заём, разархивированный вручную,
не архивируются повторно, пока остаток снова не пройдёт через ненулевое
значение. Это даёт «ручное разархивирование не перебивается» без отдельного
флага «пользователь отказался».

**D4. Состояние фильтров — на экране.** Чипы секций (`Кошельки`), поиск и чипы
направления (`Долги`), «Показывать архивные» везде живут полями экрана и
сбрасываются при каждом создании экрана (открытие приложения / вход на
экран). `PeriodFilterState` и общий фильтр шапки не трогаются. Альтернатива —
сохранять в `AppSettings`: отложено, пользователь этого не просил.

**D5. Чипы секций.** Невыбранные чипы показывают всё. Чип секции без
строк в леджере не показывается (нет активов или нет долговых кошельков).
Фильтр секций применяется после сбора секций и не влияет на расчёт сумм.

**D6. Поиск по имени.** Нормализация: без регистра, обрезка пробелов,
`ё` → `е`, подстрока как текст (без `regex`) — то же правило, что у
уникальности контрагента (`Counterparty`-ключ) и у «Поиска по названию» в
справочнике; общий метод нормализации используется везде, чтобы
«алена» находила «Алёна». На экране «Долги» поиск идёт по имени контрагента,
не по имени кошелька займа.

**D7. Направление займа — по знаку остатка.** Фильтр считается над
`Loan.balance` с допуском точности валюты (тот же `isClosed()`): `> 0` — «Мне
должны», `< 0` — «Я должен». Контрагент без подходящих займов не попадает в
результат `group()`; итоги шапки считаются отдельно от отфильтрованного списка.

**D8. Новый заём — всегда новый кошелёк.** Поведение уже такое
(`CreateDebtWallet`, имя «<контрагент> · <код>» с « · 2»); меняется только
то, что архивный заём не переиспользуется. Проверяется тестом, код не
меняется.

## Risks / Trade-offs

- [Сумма секции включает скрытые архивные, а видимые строки её не складывают] →
  принято (требование владельца: архив только для отображения); строка-подсказка
  о числе скрытых не вводится, при необходимости — отдельным change.
- [Забытый сценарий записи без вызова авто-архива] → безопасно: заём
  виден как «закрыт» и архивируется вручную; список вызывающих мест зафиксирован
  в задачах, тест на каждый.
- [Потеря займа из виду: погашен, ушёл в архив, потом правка возвращает
  остаток, а заём остался скрыт] → по решению владельца авто-разархивирования
  нет; заём виден через «Показывать архивные», итоги учитывают его.
- [Изменённое поведение таба «Кошельки»: пользователь не видит архивный
  кошелёк с остатком] → переключатель над списком; итоги не меняются.
- [Узкий экран Huawei: три чипа и поле поиска в одну строку] → чипы в
  горизонтальной прокрутке, поле поиска отдельной строкой; проверка в английской
  локали.
- [Без сети] → всё локально: флаг ставится в той же транзакции и уходит
  ближайшим синком как обычная правка счёта.

## Migration Plan

Миграции БД нет: колонка `is_archived` уже есть. Существующие погашенные
займы архивируются не сами (нет перехода) — пользователь или оставляет их
как «закрыт», или архивирует вручную. Откат — откат приложения; флаги
архива остаются данными.

## Open Questions

- Нужна ли разовая «зачистка»: архивировать при первом запуске все займы с
  нулевым остатком? Не меняет спеки и задач, решить можно при ручной проверке
  на устройстве (по умолчанию — нет).
