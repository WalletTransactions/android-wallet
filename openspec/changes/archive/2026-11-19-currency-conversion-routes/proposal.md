# Proposal

## Why

Эквивалент (остатки кошельков, итоги, эквивалент операции) считается по курсу
«A→B на дату», который берётся из одной валютной пары. Если прямой пары нет,
курса нет: кошелёк выпадает из итога, итог получает пометку `~`. Типичный случай —
BTC, оценённый в рублях: пар BTC/RUB нет, зато есть BTC/EUR и EUR/RUB.
Таблица `currency_conversion`, задуманная под такие маршруты, на деле их выразить
не может: вьюха `v_currency_conversion` строится от уже существующих пар и лишь
подменяет `pair_id` у их направлений; в таблицу при этом не пишет ни один
код-путь, а UI для маршрутов нет.

## What Changes

- Пользователь может задать **маршрут пересчёта** цепочкой шагов до трёх
  (например, `BTC → EUR → RUB`). Маршрут хранится строками
  `currency_conversion` `(from, to, num = номер шага, currency_pair_id,
  is_reverse)`, принадлежит леджеру, синхронизируется как остальные
  справочники и мягко удаляется. Маршрут двунаправленный.
- Курс составного маршрута = произведение курсов шагов; каждый шаг берёт
  последний курс не позже нужной даты независимо от других. Нет курса хотя бы
  у одного шага или цепочка недостроена/оборвана — курса маршрута нет
  (пересчёт 1:1 по-прежнему не применяется).
- Если у пары валют есть хотя бы один живой прямой курс (в любую сторону),
  маршрут для неё не применяется вовсе; он работает только там, где иначе
  курса бы не было.
- По умолчанию кросс-курсы считаются через USD: для пары без прямого курса и
  без явного маршрута курс = `A→USD` × `USD→B` по прямым курсам. Приоритет:
  прямой → явный маршрут → USD; тот же порядок, что на сервере (wallet-api),
  чтобы эквивалент на телефоне совпадал с отчётами.
- Удаление пары на устройстве снимает использующие её маршруты (как уже
  снимает её курсы).
- Вьюха `v_currency_conversion_rate` выдаёт составные курсы теми же строками
  `(from, to, date, rate)`, так что потребители (`v_operation_eq`, остатки,
  карточка периода) не меняются.
- Экран «Курсы валют» получает управление маршрутами: список маршрутов,
  добавление, удаление.
- Таблица `currency_conversion` остаётся с теми же колонками, но меняет
  смысл (шаги маршрута) и получает ограничения (`num` 1…3, `ledger_id` обязателен);
  правится вместе с wallet-api. **BREAKING** по ограничениям строки в синке
  (`/sync/push`, `/sync/pull`); совместимость со старыми клиентами не
  сохраняется.
- Затронутые сервисы: android-wallet (клиент, вьюхи SQLite, UI), wallet-api
  (схема/вьюхи Postgres, контракт синка), wallet-web (управление маршрутами в
  кабинете), wallet-report (список колонок зеркала синк-таблиц). Для остальных
  потребителей курса — без изменений. У каждого сервиса свой change с этим же
  именем; контракт синка — в wallet-api.

## Capabilities

### New Capabilities
- `currency-routes`: маршруты пересчёта валют через промежуточную валюту —
  модель маршрута, правила составного курса, приоритет прямой пары, экран
  управления маршрутами.

### Modified Capabilities
- `balances-and-equivalent`: требование «Курс на дату» — курс ищется ещё и по
  составным маршрутам; эквиваленты остатка и операции считаются по ним же.
- `currency-pairs`: экран «Курсы валют» — вход в управление маршрутами.
- `sync-data-exchange`: строки `currency_conversion` в push/pull — шаги
  маршрута с новыми ограничениями.

## Impact

- Код: `WalletDbHelper` (миграция схемы и пересоздание вьюх, поднять
  `DATABASE_VERSION`), `schema/view/v_currency_conversion*.sql`,
  `schema/table/currency_conversion.sql` и README схемы, `WalletDbCRUD` /
  `WalletDbLoader` (запись и чтение маршрутов), `sync/SyncEngine`, экран
  «Курсы валют».
- Контракты: `openapi.yaml` wallet-api (`CurrencyConversionPushRow` /
  `PullRow`).
- Данные: `currency_conversion` сегодня всегда пуста — переносить нечего.
- Риски: составной курс «стареет» по самому старому из шагов; на сервере
  вьюха используется в `balance_series` и `capital_assets`, нужна проверка
  производительности (подробности — в design).
