# Proposal

## Why

Задача [android-wallet#50](https://github.com/WalletTransactions/android-wallet/issues/50).
После «Ещё» → «Удалить данные» с «Иконки» + «Пересеять набор» синк откладывает
почти всё: «нет иконки-заместителя для «Houseware»: строка отложена», «отложено
до следующего синка (нет иконки-заместителя): 19397 строк».

`WalletFillData.ResetIcons` мягко удаляет и иконки с сервера (`origin = 0`).
Иконки в push не уходят, поэтому на сервере они живы, а pull удаление не
отменит — курсор их уже прошёл. `IconSubstitutes.load` берёт заместителей только
из живых иконок с сервера — их ноль, и для каждой своей иконки нет даже
`unknown`. Откладываются все валюты, счета на них, операции и `operation_link`;
вместе с ними застревают и удаления старых данных.

Отдельно: импорт счетов при не найденной иконке ставит `icon_id = 1`, а у валюты
ищет иконку по имени без фильтра `deleted_at IS NULL` — 22 счёта владельца
ссылаются на удалённую `Groceries` (`_id = 1`).

## What Changes

- `IconSubstitutes.load`: в заместители идут и иконки с сервера, удалённые только
  локально (`dirty = 1`) — на сервере они живы, ссылка проходит FK. Удалённые
  сервером (tombstone из pull, `dirty = 0`) по-прежнему не берутся. Этого одного
  достаточно, чтобы пострадавшая база досинкалась без миграции.
- `ResetIcons` не трогает иконки с сервера (с пересевом и без); пересев не
  заводит свою иконку с именем уже живой иконки (берёт живую).
- Импорт счетов (`WalletImportData`): иконка счёта и валюты — только живая по
  имени, иначе живая `unknown` (не `_id = 1`).
- Миграция БД v90: иконки с сервера, удалённые локально, возвращаются; своя живая
  с тем же именем и той же картинкой — счета и валюты перевешиваются на серверную,
  своя удаляется; картинка другая — своя переименовывается в «<имя> (своя)».
- Unit-тесты на всё перечисленное (`testQaDebugUnitTest`).
