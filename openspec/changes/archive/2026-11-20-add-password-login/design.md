# Design

## Context

Зачем — в `proposal.md`, требования — в `specs/server-account/spec.md`. Сейчас:
- Вход — `SyncLinkActivity` (Credential Manager → `POST /auth/nonce` →
  `POST /auth/google/mobile`); токены хранит `AuthSession` в
  `EncryptedSharedPreferences`; обновление — `POST /auth/refresh` перед проходом синка.
- Адрес сервера пользователь задаёт сам («Адрес сервера» на «Интеграциях»), по
  умолчанию — из варианта сборки; приложение может работать с любым гейтвеем.
- В манифесте стоит `usesCleartextTraffic="true"`, своего `network_security_config`
  нет; minSdk 27 / targetSdk 34, поэтому пользовательские CA для приложения по
  умолчанию не доверяются.
- Токены `device_id`/`platform` и дальнейшая жизнь сессии не зависят от способа входа.

## Goals / Non-Goals

**Goals:**
- Вход и регистрация по паролю на том же экране, что и Google; набор способов задаёт сервер.
- Работа по `https://` со своим CA, который пользователь установил на телефон.
- Всё новое — через строковые ресурсы ru и en.

**Non-Goals:**
- Переименование строки «Связь с Google аккаунтом» и связанных текстов в `sync-run`:
  оставляем, чтобы не менять десяток требований; переименование — отдельным change.
- Хранение пароля на телефоне и автозаполнение (токены остаются в
  `EncryptedSharedPreferences`, пароль не сохраняется).
- Подтверждение email, сброс пароля по почте, смена пароля с телефона (пока только
  в wallet-web).
- Вшитый в APK CA и pinning: приложение публичное, у каждого свой сервер.

## Decisions

### D1. Сервер определяет способы (`GET /auth/methods`)

Экран входа при открытии запрашивает методы и строит кнопки по ответу. Так
переключение `AUTH_METHODS` на сервере не требует нового APK. Запрос лёгкий и
без БД. При недоступном сервере экран остаётся с причиной (как «Вход без сервера»).

### D2. Тот же экран, та же ветка сессии

Вход по паролю возвращает пару токенов в теле (`platform: "android"`), как
`/auth/google/mobile`; дальнейшее — существующий `AuthSession` без изменений:
сохранение, сравнение email для смены аккаунта, обновление, «Сессия истекла».
Новая только вызывающая часть (клиент входа) и экраны.

### D3. Регистрация сразу выполняет вход

`POST /auth/register` всегда `202` и не выдаёт сессию; приложение следом вызывает
`POST /auth/login` теми же данными. Если адрес занят, вход даст `401` и
пользователь увидит нейтральное сообщение (сервер не раскрывает занятость).

### D4. `network_security_config`: системные и пользовательские CA, cleartext разрешён

`<base-config cleartextTrafficPermitted="true">` с якорями `system` и `user`.
Решение владельца: проект личный и открытый, у каждого свой сервер и свой CA, поэтому
доверие пользовательским CA нужно всем, кто работает со своим CA; вшивать
чужой CA нельзя. Цена: любой CA, который пользователь сам поставил на телефон,
получает доверие приложения — это его собственный выбор. Cleartext остаётся,
потому что `http://` в домашней сети (с `ALLOW_INSECURE_AUTH` на сервере) допустим.
Реальный запрет пароля по `http` — на сервере; в приложении только предупреждение (D5).

*Альтернатива:* убрать cleartext и оставить только https. Отвергнуто: ломает
существующие домашние установки без TLS, и это решение владельца сервера.

### D5. Предупреждение по схеме адреса

Адрес пользователь вводит сам, поэтому предупреждение строится по схеме
сохранённого адреса (`http://`), а не по ответу сервера. Не блокирует ввод.

### D6. Пароль не хранится и не логируется

Пароль живёт в поле и в теле запроса; не пишется в логи приложения и в
сохранённое состояние Activity (`android:saveEnabled` для поля пароля —
`false`, `importantForAutofill` по умолчанию).

## Risks / Trade-offs

- **Доверие пользовательским CA** → решение владельца (D4); пользовательский
  CA появляется только после явной установки на устройство.
- **Пароль по `http://`** → предупреждение на экране (D5) и отказ сервера
  `insecure_transport` с понятным сообщением.
- **Отсутствие сети при входе** → поведение «Вход без сервера» (приложение
  офлайн-первое, данные на телефоне доступны).
- **Старое название «Связь с Google аккаунтом» при входе по паролю** → путает,
  но не ломает; переименование вынесено в Non-Goals.
- **Строки и узкий экран** (Huawei P20 Pro, английская локаль) → проверка на устройстве
  в обеих локалях.

## Migration Plan

Выкатывать после google-auth (`add-password-auth`) и TLS (wallet-infra).
Старый APK продолжает работать с Google при `AUTH_METHODS=both`/`google`.
Пользователи со своим CA ставят корневой сертификат на телефон (выгружается
скриптом wallet-infra) и указывают `https://`-адрес в «Адрес сервера».
Откат — прежний APK; `network_security_config` обратно совместим.

Правки в других сервисах не нужны (wallet-gateway, wallet-api без изменений).
