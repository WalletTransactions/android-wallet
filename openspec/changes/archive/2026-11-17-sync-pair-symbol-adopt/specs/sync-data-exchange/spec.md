## MODIFIED Requirements

### Requirement: Применение загрузки по uuid
Каждая пришедшая строка SHALL сопоставляться с локальной по uuid без учёта
регистра и дефисов (на телефоне uuid бывают записаны и с дефисами, и без).
Найдена — локальная строка обновляется данными сервера, ссылки переводятся из
uuid в локальные идентификаторы; не найдена — вставляется. Журнал получает
«Добавлено», «Изменено» или «Удалено» по типам «Валюта», «Валютная пара»,
«Курс», «Счёт», «Признак актива», «Операция». Строка, вставка которой
нарушает уникальность на телефоне (например, имя или код валюты) и которую
клиент не умеет разрешить по ключу, SHALL пропускаться без ошибки прохода.
Конфликт символа валютной пары разрешается по правилам «Конфликт символа
пары» и строкой, которую можно потерять, не считается. Удаление, пришедшее
для известной строки, ставит ей время удаления (поведение для неизвестной —
см. `sync-run`). Тот же поиск по uuid используют экраны вне синка (экран «ИИ»
сверяет черновик с телефоном).

#### Scenario: Операция бота на счёт без дефисов в uuid
- **WHEN** на телефоне счёт «Наличные» записан с uuid без дефисов, а бот внёс операцию по нему, и сервер прислал uuid с дефисами
- **THEN** операция применяется к счёту «Наличные»

#### Scenario: Переименование на вебе
- **WHEN** на вебе категория «Еда» переименована в «Продукты»
- **THEN** после прохода на телефоне та же категория называется «Продукты», операции по ней на месте, журнал «↓ Изменено: Счёт × 1»

### Requirement: Однократная перезагрузка после исправлений клиента
Если на телефоне ещё не выполнялась перезагрузка потоков после исправления
поиска по uuid, после появления отложенных строк и после исправления
конфликта символа пары, первый проход SHALL один раз загрузить оба потока с
начала (с вычисткой по правилам `sync-run`) и добавить в журнал «⚠ Повторная
загрузка с сервера — подтягиваю пропущенные данные».

#### Scenario: Обновление со старой версии
- **WHEN** приложение обновилось с версии, терявшей строки без родителя
- **THEN** первый проход загружает оба потока с начала, следующие — с сохранённой позиции

#### Scenario: Обновление с версии, терявшей пары кошелька
- **WHEN** приложение обновилось с версии, которая молча отбрасывала пару кошелька, конфликтующую по символу с общей парой
- **THEN** первый проход загружает оба потока с начала, после прохода пара кошелька и её курсы на телефоне, в журнале нет «Часть данных ждёт связанных записей с сервера (currency_pair_rate: …)»

## ADDED Requirements

### Requirement: Конфликт символа пары
Пришедшая живая валютная пара, чей символ (без учёта регистра) занят другой
живой парой телефона с другим uuid, SHALL разрешаться без потери строки:
- пришла пара кошелька (`ledger_id` задан), а занявшая символ строка синкнута
  (`dirty = 0`) или неотправлена, — локальная строка берёт uuid и поля
  пришедшей, метка «из справочника» снимается, локальный идентификатор строки
  и все привязанные к ней курсы и перерасчёты сохраняются, `dirty` остаётся 0;
- пришла общая пара (`ledger_id` пуст), а символ уже занят парой кошелька, —
  пришедшая не вставляется, это штатный исход, а не ошибка, и в отложенные
  строки она не попадает;
- пришла общая пара, а символ занят неотправленной локальной парой, — как для
  пары кошелька: пришедшая заменяет локальную.
Пара с занятым символом, которую так разрешить нельзя, SHALL оставаться
отложенной и попадать в журнал «Часть данных ждёт связанных записей с
сервера», а не считаться обработанной. Правило действует при любой загрузке, а
не только во время подключения к кошельку.

#### Scenario: Пара кошелька поверх общей
- **WHEN** на телефоне есть общая пара EURRUB (uuid `886dd3d0…`, синкнута), а сервер прислал пару кошелька EURRUB с другим uuid `e852743a…`
- **THEN** на телефоне одна пара EURRUB с uuid `e852743a…`, курсы кошелька по ней применяются, диалога «Синхронизация прошла не полностью» нет

#### Scenario: Общая пара после пары кошелька
- **WHEN** на телефоне уже стоит пара кошелька EURRUB, а загрузка принесла общую EURRUB с другим uuid
- **THEN** локальная пара остаётся парой кошелька, общая не добавляется, журнал не содержит «✖ Часть данных ждёт связанных записей»

#### Scenario: Курсы уже привязаны к заменённой строке
- **WHEN** у общей пары EURUSD на телефоне уже есть курсы, а затем её заменяет пара кошелька EURUSD
- **THEN** те же курсы показываются у пары кошелька EURUSD, дубликатов нет
