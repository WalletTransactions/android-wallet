# Proposal

## Why

После `server-managed-icons` телефон не отправляет свои иконки: они остаются
только на устройстве, на счёте в синке подставляется иконка-заместитель. Нужно
вернуть отправку **по желанию пользователя**, чтобы иконки из галереи попадали
в его набор на сервере (виден на вебе в «Отчёты → Иконки → Свои» и доступен
другим устройствам). Оператор сервера может запретить приём (флаг
`LEDGER_ICON_UPLOAD`, парный change wallet-api `optional-icon-upload`);
тогда телефон должен узнать об этом и сам отключить отправку.

Обрезка и сжатие иконки на телефоне уже подходят: круглое окно, 256×256, WEBP
качества 85 с прозрачностью (`icon-library`), размер единицы — десятки КиБ,
сервер принимает до 1 МиБ. Правок в этой части не нужно.

## What Changes

- Настройка «Отправлять свои иконки на сервер» («Ещё → Настройки», раздел
  «ДАННЫЕ»), по умолчанию выключена, только на телефоне.
- При включённой настройке и разрешающем флаге сервера проход синка
  отправляет свои иконки (`origin = 1`) отдельным шагом **до** push строк:
  `HEAD`/`POST /sync/blobs`, затем таблица `icon` в `POST /sync/push`. Принятая
  иконка становится серверной (`origin = 0`) и перестаёт быть заместителем-
  кандидатом. Включение отправляет все существующие свои иконки.
- Телефон узнаёт флаг сервера из `capabilities.icon_upload` в ответе
  `GET /sync/pull` и хранит последнее известное значение. Пока значение не
  получено или `false`, переключатель неактивен с пояснением и ничего не
  отправляется.
- Отказ сервера (`403 icon_upload_disabled` на `/sync/blobs` или
  `icons_rejected` в ответе push) **выключает настройку** на телефоне,
  показывает уведомление и не считается ошибкой прохода: строки со своими
  иконками уходят с заместителем, как сейчас.
- Сбой одной иконки (сеть, `409` по имени) не откладывает счета и валюты: на
  этот проход используется заместитель, иконка уйдёт при следующем.
- **BREAKING (поведение синка):** при включённой настройке снова есть запросы
  `/sync/blobs`; спека `icon-sync` «Иконки только скачиваются» уточняется.

## Capabilities

### New Capabilities
- `icon-upload`: настройка и сценарий отправки своих иконок, зависимость от
  флага сервера, самоотключение при отказе, поведение при сбоях.

### Modified Capabilities
- `icon-sync`: «Иконки только скачиваются» — отправка допустима при включённой
  настройке; происхождение иконки меняется `1 → 0` после приёма.
- `sync-run`: «Состав прохода» — шаг отправки иконок и чтение флага при pull.
- `more-and-settings`: строка настройки в разделе «ДАННЫЕ».

## Impact

- Код: `sync/SyncEngine.java` (шаг отправки иконок перед `pushDirty`,
  реакция на отказ, ослабление `deferDependents` для иконок),
  `sync/SyncApiClient.java` (`uploadBlob`/`blobExists` возвращаются; разбор
  `capabilities`, `icons_rejected`, код 403), `sync/IconSubstitutes.java`
  (без изменений в логике), `AppSettings` (два ключа), `SettingsActivity` +
  layout + `strings.xml`/`values-en` (строка, пояснения, уведомление),
  `Activities/IconEditDialog.java` (подсказка для иконок из своего набора).
- Тесты: юнит-тесты шага отправки (успех, отказ, сбой сети, `409`, дедуп по
  картинке), разбор pull/push-ответа; обновить `SyncEngine*IconTest`.
- `docs/ARCHITECTURE.md`; версию схемы БД менять не нужно (`origin` есть с v86).
- Сервер: нужен wallet-api с change `optional-icon-upload` (флаг,
  `capabilities`, `icons_rejected`). Новый клиент на старом сервере без поля
  `capabilities` считает приём запрещённым.
