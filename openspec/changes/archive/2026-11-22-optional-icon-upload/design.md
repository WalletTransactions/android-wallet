# Design

## Context

- После `server-managed-icons` (v86): `icon.origin` (0 — с сервера, 1 — своя),
  `IconSubstitutes` строит индекс серверных иконок (sha256 картинки → uuid, имя →
  uuid, `unknown`), `PushIconRefs` подставляет заместителя в `currency`/`account`,
  `deferDependents` откладывает строки без заместителя. `SyncApiClient.uploadBlob`
  и `blobExists`, `collectDirtyIcons`, `ensureBlobUploaded` из движка удалены.
- Порядок прохода: push, затем pull. Значение серверного флага приходит только
  в pull, поэтому на момент push доступно **последнее известное** (до первого
  pull — неизвестно).
- Сервер (парный change wallet-api `optional-icon-upload`): флаг
  `LEDGER_ICON_UPLOAD`; `capabilities.icon_upload` в pull; `403
  icon_upload_disabled` на `/sync/blobs`; в push иконки отбрасываются, ответ
  `200` с `icons_rejected`. Если иконка отброшена, а в том же батче есть
  строка, ссылающаяся на неё, — `409 missing_reference` на весь батч.
- Обрезка и сжатие иконки (круг, 256×256, WEBP q85) достаточны, менять их не нужно.

## Goals / Non-Goals

**Goals:**
- Опциональная отправка своих иконок в набор «Свои» на сервере.
- Подчинение флагу сервера: заранее (pull) и по отказу.
- Сбой иконки не ломает и не откладывает синк остального.

**Non-Goals:**
- Правка/удаление иконки после отправки (см. «Открытые вопросы»).
- Перенос иконки в общий набор, отправка иконок по требованию из диалога.
- Лимиты и квоты (решено: без лимита).

## Decisions

1. **Две настройки в `AppSettings`:** `iconUploadEnabled` (выбор пользователя,
   по умолчанию false) и `serverIconUploadAllowed` (последнее известное значение
   `capabilities.icon_upload`, по умолчанию false). Эффективное условие отправки —
   обе истинны. Старый сервер без `capabilities` не меняет значение при
   разборе… но и не выставляет его: значение остаётся false, то есть «запрещено».
2. **Иконки идут отдельным push-батчем до остальных строк.** Шаг
   `pushOwnIcons(db, api, log)` выполняется в `pushDirty` перед раундами: для
   каждой живой иконки `origin = 1`, у которой нет серверного двойника по картинке
   (`IconSubstitutes.substituteFor` по SHA-256 → `null`), `blobExists` (HEAD),
   при 404 — `uploadBlob` (до 3 попыток, как раньше), затем один push-батч с
   таблицей `icon` (метаданные: name, icon_type, content_sha256). Отдельный батч
   нужен, чтобы отказ сервера по флагу (иконка отброшена) не откатил батч со
   счетами через `409 missing_reference`.
3. **Результат шага по иконке.**
   - `200` без этого `uuid` в `icons_rejected` → `origin = 0`, `dirty = 0`
     (одной транзакцией), запись в журнал.
   - `403 icon_upload_disabled` на blob **или** `icons_rejected` в ответе push →
     `iconUploadEnabled = false`, `serverIconUploadAllowed = false`, уведомление
     (`sync_icons_server_refused`), шаг прерывается, остальной проход идёт с
     заместителями.
   - `409` по имени / `5xx` / неудача после повторов → иконка остаётся
     `origin = 1`, строка в журнал, шаг идёт к следующей иконке; `IOException`
     — как «нет сети» (штатный исход).
   Откладывание строк (`deferDependents`) для иконок при этом **не** включается:
   `PushIconRefs` и так подставляет заместителя; строка без заместителя
   откладывается как сейчас.
4. **Чтение флага в pull.** `SyncApiClient.PullResult` получает необязательное
   поле `iconUploadAllowed` (`capabilities.icon_upload`, `false` если блока нет).
   `SyncEngine` после успешного pull пишет его в `serverIconUploadAllowed`; если
   значение стало `false` при включённой настройке — настройка выключается и
   показывается то же уведомление (флаг выключили, пока телефон ничего не
   отправлял).
5. **Включение настройки не требует отдельной метки dirty.** Шаг выбирает иконки
   по `origin = 1` и `deleted_at IS NULL`, а не по `dirty`: миграция v86 обнулила
   `dirty`, а триггер `trg_icon_dirty` ставит его на любой UPDATE — надёжнее
   смотреть на происхождение.
6. **Дедупликация по картинке:** своя иконка, чей SHA-256 совпал с иконкой
   с сервера, не загружается (экономит трафик и не плодит дубли); её роль уже
   играет заместитель. Она остаётся `origin = 1`.
7. **UI.** `SettingsActivity`: строка-переключатель в «ДАННЫЕ», состояния
   «активен / неактивен с пояснением». Строки — `strings.xml` и `values-en`
   (проверка английской локали на Huawei, узкий экран). `IconEditDialog` для
   иконок `origin = 0` остаётся режимом просмотра; текст подсказки «Иконка с
   сервера — изменить или удалить её может администратор на сайте.» остаётся
   (правка собственных серверных иконок — вне этого change).

**Правки в других сервисах:** wallet-api — парный change `optional-icon-upload`
(флаг, `capabilities`, `icons_rejected`). wallet-infra — переменная
`LEDGER_ICON_UPLOAD`. wallet-web — без правок: «Свои» уже показываются.
wallet-telegram не затронут.

**Без сети / при отказе сервера:** без сети шаг иконок прерывается как любая
отправка («нет сети»), иконки остаются своими и уйдут позже. Отказ по флагу —
самоотключение без ошибки. Старый сервер без `capabilities` — переключатель
неактивен, отправки нет.

## Risks / Trade-offs

- [Флаг на сервере выключили между pull и push] → шаг иконок получает `403` или
  `icons_rejected`, настройка выключается, проход продолжается с
  заместителями; отдельный батч иконок не даёт откатить остальной push.
- [Первый проход после включения с большим числом иконок] → иконки идут по
  одной с журналом; сбой одной не мешает остальным; повтор в следующем проходе.
  Вес одной иконки — единицы или десятки КиБ.
- [После отправки иконка становится «серверной» и не правится] → осознанное
  ограничение первого шага; пользователь теряет возможность удалить свою
  иконку с телефона. Если это болезненно — отдельный change (правка/удаление
  своих серверных иконок через API wallet-api).
- [Иконка отправлена, но у другого устройства того же леджера есть одноимённая
  своя] → конфликт имени обрабатывается уже существующим переименованием на
  pull (« (своя)»), см. `icon-sync`.
- [Трафик по Tailscale-relay] (инцидент 2026-10-11) → отдельный шаг, не блокирующий
  основной push, делает его ограниченным по ущербу.

## Migration Plan

Миграции БД нет. Выкатка после wallet-api с флагом (по умолчанию off) — новый
клиент на старом сервере просто не включает переключатель. Порядок: wallet-api →
wallet-infra (test: `LEDGER_ICON_UPLOAD=on`) → проверка на телефоне (Huawei P20 Pro,
русская и английская локали) → релиз Android.

## Open Questions

- Нужна ли правка/удаление своих иконок, уже ушедших на сервер (иначе они
  «навсегда» в наборе)? Предлагается отдельным change.
