# Spec Delta

## Purpose

Импорт банковской выписки на телефоне: файл уходит в wallet-ai, тот разбирает
строки и предлагает категории, пользователь проверяет список и записывает
расходы в базу телефона. Проверку на дубли делает телефон по полям операций, а
не сервер.

## ADDED Requirements

### Requirement: Вход на экран «Выписка»
Экран «ИИ» SHALL показывать раздел «Выписка из банка» с кнопкой «Загрузить
выписку», которая открывает экран «Выписка». Приложение SHALL принимать файл
через «Поделиться» (PDF, CSV, текст) и открывать экран «Выписка» с этим
файлом.

#### Scenario: Поделились PDF из банка
- **WHEN** пользователь в банковском приложении выбирает «Поделиться» → «Кошелёк» для файла `statement.pdf`
- **THEN** открывается экран «Выписка» с файлом `statement.pdf`, загрузка не начата

#### Scenario: Выбор файла
- **WHEN** пользователь на экране «ИИ» нажимает «Загрузить выписку»
- **THEN** открывается экран «Выписка» и системный выбор файла

### Requirement: Выбор кошелька и загрузка
Перед загрузкой экран SHALL предложить выбрать кошелёк выписки из живых
неархивных кошельков. «Загрузить» SHALL сначала выполнить синк, затем
отправить файл в `POST /api/ai/imports` (wallet-ai, `operationId:
createImport`). Файл больше 5 МБ не отправляется.

#### Scenario: Кошелёк создан на телефоне
- **WHEN** пользователь создал на телефоне кошелёк «Revolut» без синка и загружает выписку на него
- **THEN** синк отправляет «Revolut» на сервер, затем импорт создаётся

#### Scenario: Большой файл
- **WHEN** выбран файл 6 МБ
- **THEN** экран показывает «Файл больше 5 МБ — разбейте выписку по месяцам», запрос не отправляется

### Requirement: Отказы загрузки
Экран SHALL показывать причину отказа `POST /api/ai/imports` и не терять
выбранные файл и кошелёк.

#### Scenario: Скан без текста
- **WHEN** импорт создан сразу в `failed` с `failure: no_text`
- **THEN** экран показывает «В PDF нет текста — это скан. Нужна выписка с текстовым слоем»

#### Scenario: Не выписка
- **WHEN** импорт создан сразу в `failed` с `failure: no_operations`
- **THEN** экран показывает «В файле не нашлось операций»

#### Scenario: Уже идёт другой импорт
- **WHEN** сервер отвечает 429 `import_in_progress`
- **THEN** экран показывает «Уже разбирается другая выписка» и открывает её

#### Scenario: ИИ выключен
- **WHEN** сервер отвечает 503
- **THEN** экран показывает «ИИ сейчас выключен»

### Requirement: Ожидание разбора на открытом экране
Пока экран открыт, он SHALL опрашивать `GET /api/ai/imports/{id}` и
показывать «Разбираю выписку: <done> из <total>»; при `paused_since` —
«Разбор на паузе: ИИ недоступен». Уход с экрана SHALL прекращать опрос, не
отменяя разбор. Открытие экрана SHALL находить незавершённый импорт через
`GET /api/ai/imports` и продолжать.

#### Scenario: Вернулся позже
- **WHEN** пользователь загрузил выписку, ушёл с экрана, а через 5 минут открыл «Выписка» снова
- **THEN** экран находит этот импорт и показывает его состояние, не предлагая загрузить заново

#### Scenario: Пауза
- **WHEN** ответ содержит `paused_since`
- **THEN** экран показывает «Разбор на паузе: ИИ недоступен»

### Requirement: Список строк
При `status` `ready` или `done` экран SHALL показать строки импорта: дата,
сумма, продавец (`description`), категория (своя или предложенная моделью) и
состояние строки. Список SHALL браться с сервера при каждом открытии; без
сети экран показывает «Нет связи с сервером — список недоступен».

#### Scenario: Список открыт
- **WHEN** импорт `ready` с 40 строками
- **THEN** экран показывает 40 строк с датой, суммой, продавцом, категорией и состоянием

### Requirement: Состояния строки
Экран SHALL показывать у строки одно состояние, по порядку проверки:
«Добавлена» (на телефоне есть живая операция с `uuid = row_id`), «Не для
записи» (не расход или незнакомая группа сервера), «Проверить» (`check` не
пуст), «Похоже, уже есть: <дата> <сумма> <категория>» (дубль по полям),
«Нужна категория» (категории нет), «Ждёт».

#### Scenario: Строка-доход
- **WHEN** строка с `dir: income`
- **THEN** состояние «Не для записи», кнопок записи у строки нет

#### Scenario: Незнакомая группа
- **WHEN** сервер прислал строку с группой `ignored`, которой приложение не знает
- **THEN** строка показывается как «Не для записи» с исходной строкой выписки, экран не падает

#### Scenario: Сумма не сверилась
- **WHEN** у строки `check: amount_not_in_text`
- **THEN** состояние «Проверить», строка не попадает в «Записать готовые»

### Requirement: Проверка на дубли по полям
Для каждой недобавленной строки-расхода приложение SHALL искать в базе
телефона живую операцию с кошелька выписки на ту же сумму с датой ±1 день, не
записанную из этого импорта. Каждая операция закрывает не больше одной строки;
строкам по порядку дат достаётся ближайший по дате кандидат. Группы сервера
`exists`, `imported`, `possible_duplicate` не учитываются.

#### Scenario: Уже внесено вручную
- **WHEN** на телефоне есть операция 12.10 450,00 «Такси» с кошелька выписки, а в выписке строка 13.10 450,00 YANDEX*GO
- **THEN** у строки состояние «Похоже, уже есть: 12.10 450,00 Такси»

#### Scenario: Два кофе, один внесён
- **WHEN** в выписке две строки 12.10 200,00 COFFEE, а на телефоне одна операция 12.10 200,00 с этого кошелька
- **THEN** одна строка «Похоже, уже есть», вторая «Ждёт»

#### Scenario: Повторная загрузка той же выписки
- **WHEN** выписку за сентябрь загрузили второй раз после того, как все её строки записаны
- **THEN** все строки-расходы второй загрузки — «Похоже, уже есть»

#### Scenario: Сервер считает дублем, телефон нет
- **WHEN** у строки серверная группа `exists`, а на телефоне подходящей операции нет
- **THEN** состояние строки определяется без учёта группы сервера, например «Ждёт»

### Requirement: Запись строки через окно операции
Тап по строке «Ждёт», «Нужна категория», «Проверить» или «Похоже, уже есть»
SHALL открыть окно «Новая операция» с кошельком выписки, категорией строки,
суммой, датой, продавцом в комментарии и `uuid = row_id`. Тап по
«Добавлена» SHALL открыть эту операцию на правку.

#### Scenario: Правка суммы и категории
- **WHEN** пользователь открыл строку 1290,00 PEREKRESTOK, исправил сумму на 1209,00, выбрал «Продукты» и нажал «Сохранить»
- **THEN** на телефоне операция 1209,00 «Продукты» с `uuid = row_id`, строка — «Добавлена»

#### Scenario: Подсказка модели
- **WHEN** у строки нет категории, а `suggestion` — «Кафе»
- **THEN** в выборе категории «Кафе» стоит первой

### Requirement: Отметка записанного на сервере
После записи строки приложение SHALL отправить выбранную категорию, если она
отличается от серверной, в `PATCH /api/ai/imports/{id}/rows` (только
`category_uuid`) и отметить строку в `POST /api/ai/imports/{id}/committed`.
Сумма и дата на сервер не отправляются. Неудачная отметка SHALL повторяться
при следующем открытии списка.

#### Scenario: Сервер выучил продавца
- **WHEN** пользователь записал строку PEREKRESTOK с категорией «Продукты», которой не было у строки
- **THEN** сервер получает `category_uuid` «Продуктов» для этой строки, остальные строки PEREKRESTOK в списке получают «Продукты»

#### Scenario: Отметка без сети
- **WHEN** строка записана на телефоне, а `POST /committed` не прошёл по сети
- **THEN** строка «Добавлена»; при следующем открытии списка приложение отмечает её на сервере

### Requirement: Записать готовые
Кнопка «Записать готовые (N)» SHALL записывать одной транзакцией строки в
состоянии «Ждёт», у которых категория выбрана, кошелёк и категория живы на
телефоне, сумма положительна и дата не в будущем. Затем — отметка на сервере и
фоновый синк. N — число таких строк; при N = 0 кнопка неактивна.

#### Scenario: Пачка
- **WHEN** в списке 30 строк «Ждёт» с категорией, 5 «Нужна категория» и 3 «Похоже, уже есть»
- **THEN** кнопка «Записать готовые (30)»; после нажатия 30 строк «Добавлена», остальные 8 без изменений

#### Scenario: Категории нет на телефоне
- **WHEN** у строки «Ждёт» категория, удалённая на телефоне
- **THEN** строка не входит в «Записать готовые» и показывает «Категории «<имя>» нет на телефоне»

### Requirement: Без сети после открытия
Если список уже открыт, а сеть пропала, запись строк SHALL работать: операции
пишутся на телефон, отметки на сервере откладываются.

#### Scenario: Записал в метро
- **WHEN** список открыт, сеть пропала, пользователь записал 3 строки
- **THEN** 3 операции на телефоне, строки «Добавлена»; отметки уйдут при следующем открытии списка с сетью
