# Proposal

## Why

После включения HTTPS на test (wallet-infra `add-tls-ingress`, порт 8444) Pixel 7
перестал синхронизироваться. На экране было только «Сервер недоступен», в Telegram-строке
тоже «Сервер недоступен». Настоящую причину удалось найти лишь в logcat:
`CertPathValidatorException: Trust anchor for certification path not found`. На телефон
не был установлен корневой сертификат CA сервера.

Java сводит DNS, отказ соединения, таймаут и проблемы сертификата к одному
`IOException`. Приложение показывало для всех них одинаковый текст, а иногда добавляло
сырое сообщение исключения на английском. Пользователь не мог понять, что исправлять:
адрес, сеть или сертификат.

## What Changes

- Причина сетевой ошибки определяется по типу исключения и цепочке причин: сертификат
  не доверен, сертификат просрочен, сертификат выписан на другое имя, прочая ошибка TLS,
  имя не найдено, соединение отклонено, таймаут, прочее.
- Для каждой причины есть понятный текст с подсказкой, что сделать (ru и en). Его
  показывают диалог «Синхронизировать сейчас» и экран входа.
- Строка «Подключение к Telegram» короткая. При проблеме с сертификатом в ней
  «Ошибка сертификата», при прочих сетевых ошибках — «Сервер недоступен», как раньше.
- Обновление сессии (`POST /auth/refresh`) запоминает причину сетевой ошибки, чтобы
  синк и Telegram показали её, а не общее «Сервер недоступен по сети».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `server-account`: новое требование «Причина сетевой ошибки»; уточнены «Обновление
  сессии» и «Доверие к сертификатам».
- `sync-run`: исход «нет сети» несёт причину из «Причины сетевой ошибки».
- `telegram-link`: «Ошибка сертификата» в строке и в списке ошибок запросов.

## Impact

- Код: `sync/NetworkErrors` (новый), `sync/AuthSession`, `sync/SyncRunner`,
  `sync/TelegramLinkClient`, `Activities/SyncLinkActivity`, `Texts.context()`, строки
  `strings_sync.xml` (ru, en).
- Другие сервисы не меняются.
