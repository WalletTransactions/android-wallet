# Design

## Context

Справка по системе (`wallet-docs`) ищет по чанкам OpenSpec: `## Purpose` — отдельный
чанк, каждое `### Requirement:` со всеми сценариями — отдельный. Область по токену
у Android — только репозиторий `android-wallet`, вид `spec`. Существующие спеки
`android-wallet` (`operation-entry`, `ai-expense-entry`, `ai-statement-import`,
`debts`, `server-account`, …) написаны для разработчика: эндпоинты, `operationId`,
идемпотентность. Поэтому на «Как добавить трату?» поиск поднимает техническую спеку, а
ответ пересказывает `POST`. См. proposal.md — мотивация.

Образец — спека `user-guide` в `wallet-web` (change `add-user-guide-spec` там же,
архивирован 2026-11-22): тот же приём, проверенный живыми вопросами к «Справке».

Названия кнопок и экранов взяты дословно из спек `period-summary`, `operation-entry`,
`ai-expense-entry`, `ai-statement-import`, `debts`, `wallets-tab`, `reports`,
`recurring-operations`, `reminders`, `server-account`, `telegram-link`,
`data-export`, `data-import`, `app-lock`, `ui-language`, `docs-assistant`,
`more-and-settings` и строк ресурсов `values-ru/strings.xml`; задача 1.1 сверяет их с живым приложением.

## Goals / Non-Goals

**Goals:**
- Один вопрос пользователя — один чанк: заголовок повторяет, как люди спрашивают, текст — шаги по названиям с экрана.
- Ответ на «Как добавить трату?» и «Как перевести деньги с карты в наличные?» — на языке пользователя и по существу.
- Правда о возможностях: перевод создаётся только в приложении Android, в вебе он виден, но не создаётся; чат «Спросить» есть только в вебе, поэтому спека не обещает его в Android.

**Non-Goals:**
- Менять `wallet-docs`: ни виды, ни область, ни ранжирование. Если ответы не улучшатся, это отдельный change в `wallet-docs`.
- Менять код приложения или тексты интерфейса.
- Дублировать поведение экранов: сценарии ссылаются на названия, а правила проверок и ошибок остаются в спеках экранов.

## Decisions

**Новая спека `user-guide` в android-wallet, а не правка существующих.** Нормативный
текст для разработчика и текст для пользователя ломают друг друга и перегружают чанк;
технические спеки остаются точными и неизменными.

**Формат требования — факт для пользователя первым, `SHALL` последним.** Справка
пересказывает начало чанка почти дословно; в веб-версии заголовок «Справка SHALL
объяснять…» в начале попал в ответ. Поэтому предложение с `SHALL` стоит в конце, а
начало — готовый ответ с названиями кнопок.

**Без возможностей, которых в Android нет.** Нет чата «Спросить» (он только в вебе),
поэтому его место занимает требование о «Вопросе по приложению». Нет приглашения человека
в леджер и сравнения периодов — они есть только в вебе; спека о них молчит, чтобы справка не
придумывала шагов.

**Требование «Ответы без внутренних терминов» проверяется вопросом, а не кодом.**
Сервис ответа не меняется; требование задаёт приёмку живым запросом к «Справке» и
защищает от ухудшения при будущих правках текста.

**Другие сервисы:** правок `wallet-docs`, `wallet-gateway`, `wallet-ai`, `google-auth`
не требуется. Индекс заливает `wallet-infra/infra/env/docs-index.sh <env> <repo>` из
рабочей папки репозитория (не из git); ночное задание `docs-index` обновляет только
test. Файлы в `openspec/changes/<имя>/` получают вид `change` и доступны только
администратору, поэтому спека синхронизируется в `openspec/specs/user-guide/spec.md`
(`openspec-sync-specs`) до приёмки, а change архивируется после неё с `--skip-specs`.

**Приёмка живыми вопросами, а не тестами.** Платформа справки определяется токеном:
Android-токен получает вход через `platform = android`; проверяем под пользователем
с этим платформенным токеном (или через тестовый скрипт с `platform: android`).

## Risks / Trade-offs

- [Тексты устареют при смене интерфейса] → каждый change, меняющий названия кнопок или пунктов меню, правит и `user-guide`; поиск по названию в спеке — проверка в задачах экрана.
- [Модель всё равно ответит технично] → ответ строится по найденным чанкам; если `user-guide` не поднимается, проверить ранжирование и открыть change в `wallet-docs`, не ослабляя требования.
- [Два места с названиями кнопок] → `user-guide` ссылается на дословные названия из спек экранов; при расхождении правда — в спеке экрана.
- [Спека длинная: около 20 чанков] → каждое требование отвечает на один вопрос и читается отдельно; общий объём не влияет на поиск.
