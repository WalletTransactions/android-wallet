# Spec Delta

## Purpose

Вид категории — «расход», «доход» или «оба»: явный признак на строке `account`,
по которому окно операции разделяет «Статью расхода» и «Статью дохода». Здесь
описаны значения, правило для кошельков и системных категорий, синхронизация с
сервером (контракт — спека `category-kind` и `openapi.yaml` wallet-api),
стартовый набор и JSON-обмен.

## ADDED Requirements

### Requirement: Вид категории
Каждая строка счёта в локальной базе SHALL хранить `category_kind` с закрытым
набором значений: `0` — расход, `1` — доход, `2` — оба. Колонка обязательна, по
умолчанию `2`. Для кошелька и системной категории (Transfer, Transfer commission,
«Переоценка») значение SHALL быть `2`: вид у них не задаётся и в интерфейсе не
показывается. Значение вне `0..2`, пришедшее извне, SHALL читаться как `2`.

#### Scenario: Обновление приложения
- **WHEN** приложение с версией базы до v92 запускается на версии с этой правкой
- **THEN** у всех счетов появляется `category_kind` = 2, строки не помечаются неотправленными и не меняют `seq`/`updated_at` на сервере

#### Scenario: Кошелёк
- **WHEN** пользователь заводит кошелёк
- **THEN** у него `category_kind` = 2, а выбора вида на экране нет

### Requirement: Вид уходит на сервер и приходит с сервера
Каждая строка `account` в `POST /sync/push` SHALL содержать `category_kind`:
сервер без него отвечает `400 invalid_row`, и пачка не применяется. Строка
`account` из `GET /sync/pull` SHALL применяться вместе со своим `category_kind`.
Если в пришедшей строке поля нет (сервер без этой колонки), клиент SHALL
принять `2`, а не отложить или пропустить строку. Вид, пришедший с сервера,
SHALL NOT помечать строку неотправленной.

#### Scenario: Отправка новой категории
- **WHEN** пользователь создал категорию «Подработка» с видом «Доход» и запустил синхронизацию
- **THEN** строка `account` в push несёт `"category_kind": 1`, при следующей загрузке на другом устройстве категория приходит с видом «Доход»

#### Scenario: Разметка с сервера
- **WHEN** сервер отдал строки `account` с `category_kind` 0 и 1 для существующих категорий
- **THEN** локально у этих категорий виды обновляются, строки не уходят обратно на сервер

#### Scenario: Сервер без поля
- **WHEN** строка `account` пришла без `category_kind`
- **THEN** она применяется с видом «Оба», в журнале нет пропущенной строки

### Requirement: Смена вида не меняет операции
Смена вида категории в карточке SHALL менять только саму категорию: операции с
ней, их суммы и проводки остаются прежними. Категория с операциями «не того»
вида SHALL оставаться в журнале, отчётах и фильтрах как есть — вид влияет
только на выбор статьи при вводе операции.

#### Scenario: Расход по категории дохода
- **WHEN** у категории «Зарплата» вид «Доход», а в журнале есть операция «Наличные → Зарплата»
- **THEN** операция остаётся в журнале и отчётах, при её правке «Статья расхода» показывает «Зарплата»

### Requirement: Вид в стартовом наборе
Стартовый набор (`starter-set`) SHALL задавать вид своих категорий: 23 расходные
категории — «Расход» (`0`), «Зарплата», «Подработка», «Проценты» и «Прочие
доходы» — «Доход» (`1`). Кошельки набора и системные категории — `2`. Запись
набора без `category_kind` SHALL читаться как `2`.

#### Scenario: Новая установка
- **WHEN** приложение впервые запускается на пустой базе
- **THEN** «Продукты» имеет вид «Расход», «Зарплата» — «Доход», кошелёк «Наличные» — «Оба»

#### Scenario: Окно операции на новой установке
- **WHEN** пользователь открывает «Статья дохода» сразу после установки
- **THEN** в списке «Зарплата», «Подработка», «Проценты», «Прочие доходы», расходных категорий нет

### Requirement: Вид в JSON-обмене
JSON-экспорт SHALL писать у каждого элемента `accounts`, являющегося обычной
категорией, целое поле `category_kind` (`0`/`1`/`2`). JSON-импорт SHALL читать его
необязательным: нет поля или значение вне `0..2` — вид «Оба». Файлы, выгруженные до
этой правки, SHALL импортироваться без ошибок.

#### Scenario: Круг экспорт — импорт
- **WHEN** пользователь экспортирует базу с категорией «Зарплата» вида «Доход» и импортирует файл на пустую базу
- **THEN** у «Зарплаты» после импорта вид «Доход»

#### Scenario: Старый файл
- **WHEN** импортируется файл без `category_kind` в счетах
- **THEN** импорт проходит, у всех категорий вид «Оба»
