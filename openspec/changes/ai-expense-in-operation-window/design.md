# Design

## Context

Зачем — в proposal.md. Что есть в коде:

- `AiActivity` после разбора строит карточку: поля, пикеры через `AlertDialog`,
  блок ошибки «пропал» (`DraftReconciler`), проверки, запись через
  `WalletDbCRUD.InsertOperation`.
- `TransactionActivity` открывается с extras `cDate`, `cAmount`, `cFrom`,
  `cTo`, `cComment`, `cKind`; счета выбираются через `AccountPickerActivity`.
  При сохранении и при удалении возвращает `RESULT_OK` с `cTranId` (у новой
  операции −1) — по результату не понять, что именно сохранено.
- В окне нет проверки «дата в будущем»; точность суммы держит клавиатура
  (`precisionOf`); нулевая сумма — «Сумма операции должна быть больше нуля».
- `add-ai-statement-import` (задача 1.4) добавляет в пикер категорий подсказку
  по имени (`suggestion`).

## Goals / Non-Goals

**Goals:**
- одно окно правки для свободной формы, выписки и ручного ввода;
- подсказки resolver видны там, где пользователь выбирает счёт.

**Non-Goals:**
- изменение разбора, синка перед ним и сверки с телефоном — как в
  `ai-expense-entry`;
- новые проверки в окне операции (дата в будущем остаётся разрешённой, как
  при ручном вводе).

## Decisions

### 1. Окно возвращает id сохранённой операции

Новый extra результата `cSavedOperationId` — `_id` главной проводки после
сохранения; при удалении его нет. Экран «ИИ» по нему читает операцию из базы и
строит «Записано: …» и `default_wallet_uuid` по факту, а не по черновику:
пользователь мог сменить сумму, кошелёк или вид операции.

Альтернатива — заранее заданный uuid (`cOpUuid` из `add-ai-statement-import`).
Не берём: свободной форме не нужна идемпотентность записи, а зависимость от
другого change задержала бы этот.

### 2. Приоритетные счета и подсказка — общий механизм окна

Окно принимает:
- `cHint` — текст строки «Подсказка ИИ: …» над полями (скрыта, если пусто);
- `cPriorityWalletIds`, `cPriorityCategoryIds` — `int[]` локальных `_id`,
  которые пикер ставит первыми в указанном порядке.

`AccountPickerActivity` получает `cPriorityIds`: эти счета — отдельной группой
сверху, дальше обычный список без них. Подсказка импорта выписки
(`suggestion` по имени) сводится к тому же: экран импорта переводит имя в `_id`
и передаёт один приоритетный счёт. Механизм делает тот change, который
реализуется первым; второй его использует.

Кандидаты resolver переводятся в `_id` через `DraftReconciler` — пропавшие с
телефона в приоритет не попадают.

### 3. Когда окно открывается сразу, а когда — блок ошибки

```
черновик -> DraftReconciler
   |
   +-- found-поля живы (или resolver их не выбрал) --> окно операции
   +-- found-поле пропало / все кандидаты пропали --> блок ошибки на «ИИ»
                                                       |-- Синхронизировать и повторить
                                                       +-- Открыть операцию (поле пусто)
```

Блок ошибки остаётся на экране «ИИ», а не в окне: в нём кнопка синка и
детали, окну операции они чужие.

### 4. Черновик живёт до записи или нового разбора

Последний черновик (`ParseExpenseResult`, исходный текст, исход синка) хранится
в `AiActivity` и в `onSaveInstanceState` — как JSON. «Открыть снова» строит те
же extras без запроса к ИИ. Сбрасывается после сохранения и при новом
«Разобрать».

### 5. Тексты подсказки — в `AiTexts`

Строка подсказки собирается из исходного текста, вопроса resolver («С какого
кошелька?», «Какая категория?»), `currency_mismatch`, `reject` и `notes` —
одной функцией в `ai/AiTexts` под юнит-тестом. Формулировки — из спеки.

### Правки в других сервисах

Нет.

## Risks / Trade-offs

- [В окне нет проверки «дата в будущем»; карточка её имела] → осознанно: окно
  ведёт себя как ручной ввод. Сервер (`parse_expense`) и так отклоняет
  будущую дату (`future_date`).
- [Пользователь сменил в окне расход на перевод] → сохраняется как перевод;
  «Записано» строится по сохранённой операции (решение 1).
- [Окно сохранило, а процесс убит до возврата] → операция в базе; экран «ИИ»
  после восстановления показывает черновик с «Открыть снова». Повторное
  сохранение создаст вторую операцию — как при ручном вводе, uuid случайный.
- [Пересечение с `add-ai-statement-import` в пикере] → решение 2: общий
  `cPriorityIds`, делает первый реализуемый change.
