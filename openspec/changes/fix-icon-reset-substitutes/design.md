# Design

## Контекст

Иконки ведёт сервер (archive `2026-11-04-server-managed-icons`): `icon.origin = 0` —
«с сервера», `1` — «своя»; push иконки не отправляет, `trg_icon_dirty` по-прежнему
ставит `dirty = 1` при любой локальной правке. Значит, у иконки с сервера
`deleted_at IS NOT NULL AND dirty = 1` — удаление только локальное, на сервере она
жива; `deleted_at IS NOT NULL AND dirty = 0` — tombstone из pull (удалил
администратор), на сервере её нет.

## Решения

1. **Заместитель (`IconSubstitutes.load`).** Условие
   `origin = 0 AND (deleted_at IS NULL OR dirty = 1)`. Порядок кандидатов прежний —
   по `_id`; живые и локально удалённые не различаются: ссылка на любую из них
   проходит FK на сервере. Тот же индекс использует `PullIconGuard` — симметрия
   push/pull сохраняется: телефон не затирает свою иконку заместителем, который сам
   бы и отправил. Миграция не нужна — следующий синк пострадавшей базы отправит
   отложенное.
2. **`ResetIcons`.** Оба режима (с пересевом и без) удаляют только `origin = 1`.
   Перепривязка по имени после пересева находит живую серверную иконку, если своя
   с таким именем не заведена.
3. **Пересев.** Все сеятели иконок (`FillCurrenis`, `InsertSpareFlagIcons`,
   `SeedDefaultCurrencyFlagIcons`, `SeedDefaultCategoryIcons`) идут через
   `SeedIcon`: живая иконка с таким именем уже есть (любого происхождения) — её
   `_id`, своя не заводится. Раньше вставка упиралась бы в `uq_icon_name` и
   молча возвращала `-1`; на чистой базе поведение не меняется.
4. **Импорт (`WalletImportData.InsertOrUpdateAccount`).** Иконка счёта — живая по
   имени из базы (`WalletFillData.GetIconIdByName`, уже с `deleted_at IS NULL`), а не
   из кэша `IconList`; не нашлась — живая `unknown`, нет и её — заводится
   (`EnsureLiveUnknownIcon`). Вместо прежнего `iconId = 1`, который и привёл 22 счёта
   на удалённую `Groceries`. Иконка валюты — тот же поиск вместо `LEFT JOIN icon`
   без фильтра и `COALESCE(i._id, 1)`.
5. **Починка уже пострадавших баз — миграция v90** (`WalletDbHelper.onUpgrade` —
   единственное «один раз при старте» в приложении). Для каждой иконки с сервера
   `deleted_at IS NOT NULL AND dirty = 1` по `_id`:
   - живая с тем же именем — своя с той же картинкой (байты `image` равны): у
     `account`/`currency` `icon_id` своей → серверная, своя мягко удаляется;
   - своя с другой картинкой — переименовывается в «<имя> (своя)» / «(своя 2)» …
     (`OwnIconNames.freeOwnName`, тот же код, что у pull — вынесен из
     `SyncEngine.OwnIcon`);
   - живая с тем же именем — с сервера (не должно случаться) — эта не
     возвращается;
   - затем `deleted_at = NULL, dirty = 0` одним `UPDATE`: `dirty` меняется 1→0,
     триггер молчит.
   После — `RepairOrphanedIconLinks` (как v78): счета/валюты на удалённых иконках
   (те 22 на `Groceries`) перевешиваются на живую с тем же именем.
   Перевешенные счета и валюты становятся `dirty` (триггер) и уходят в push с тем же
   `icon_uuid`, что раньше давал заместитель, — серверу это ничего не меняет.
6. **Сервисы.** Правок в wallet-api и других сервисах нет. Офлайн: всё —
   локальные правки базы, сеть не нужна; при отказе сервера отложенное остаётся
   `dirty` как раньше.

7. **Тест `HardWipeCacheInvalidationTest`.** Сценарий «импорт после вайпа без
   `reload*` падает на FK» больше не воспроизводится: импорт берёт иконку из базы, а не
   из кэша. Тест переписан на «импорт проходит» — это и есть новое поведение.

## Найдено попутно (не в этой задаче)

- Импорт счёта с новой валютой (`currency` с `iso`, которой нет на телефоне) падает на
  `NOT NULL constraint failed: currency.symbol`: вставка валюты в
  `WalletImportData.InsertOrUpdateAccount` не задаёт `symbol` — и до этого изменения тоже.

## Риски

- Миграция идёт на каждой базе v89. На здоровой базе нет иконок с сервера с
  `dirty = 1` — шаг ничего не меняет, кроме `RepairOrphanedIconLinks`, который уже
  безопасен (v78).
- Локально удалённая иконка с сервера в заместителях: если администратор удалит её
  на сайте после того, как телефон её удалил локально, pull принесёт tombstone и
  поставит `dirty = 0` — она выпадет из кандидатов, как и должна.
