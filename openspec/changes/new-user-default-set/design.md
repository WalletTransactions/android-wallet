# Design

## Context

- Пустая база заполняется в `WalletDbHelper.onCreate` →
  `WalletFillData.InsertFirstDictionary` из `assets/seed.json`; тот же сид —
  у пересева в `ResetDataActivity`. Все сеянные строки получают `dirty = 1`
  (DEFAULT колонки), то есть ждут отправки.
- Проход синка — `SyncRunner`: refresh → push → pull → purge. Отправка идёт
  первой.
- Локальная уникальность глобальная: `currency.iso_code`, `currency.name`,
  `currency_pair.symbol`, `account.name` (частичные индексы). Столкновение на
  загрузке (`SyncEngine.upsertByUuid`) сейчас пропускает пришедшую строку с
  записью в лог. Для `account` сервер на push отвечает 409 `duplicate_name` +
  `existing_uuid` (`resolveAccountConflicts`); для валют и пар такого нет.
- У иконок уже есть похожий приём: встроенная иконка с той же картинкой
  становится серверной (`icon-sync`, «Та же картинка не дублируется»).
- На сервере общие строки (`ledger_id IS NULL`, поток `reference`) бывают у
  иконок, валют, пар и курсов; у `account` `ledger_id NOT NULL` — общих
  категорий нет. Кошелёк создаётся пустым при первом входе
  (wallet-api `provisioning.cpp`, `create_ledger_owned_by`).

## Goals / Non-Goals

**Goals:**
- Новый человек без входа получает рабочий общий набор.
- Набор попадает в кошелёк на сервере ровно один раз — от первого
  наполнившего его телефона.
- Подключение к живому кошельку не плодит дубли и не возвращает удалённое.

**Non-Goals:**
- Набор для веба и бота (новый человек с веба получает пустой кошелёк).
- Предложение старым пользователям новых категорий из новой версии набора.
- Слияние дублей вне подключения (общая валюта, появившаяся у уже
  синкнутой своей с тем же кодом, по-прежнему пропускается на загрузке).
- Наполнение общего справочника на сервере.

## Decisions

### D1. Набор живёт только в APK

Шаблон категорий — часть приложения, сервер о нём не знает: для него это
обычные категории, созданные клиентом. Признак «набор применён» на сервере
не нужен: телефон сам видит при подключении, пуст ли кошелёк.

*Альтернатива:* копировать шаблон в `provisioning` wallet-api. Отвергнута:
при офлайн-старте телефон и сервер наполняют кошелёк каждый своей копией,
удалённое на телефоне возвращается загрузкой, переименованное двоится.

**Правка в других сервисах:** не нужна ни в wallet-api, ни в google-auth,
wallet-gateway, wallet-ai.

### D2. Состав набора

- Категории — на русском, общие, без банков и мест. Системные `Transfer` и
  `Transfer commission` сохраняют прежние имена: по ним `stampSystemCategories`
  ставит `system_kind`, и такие же имена у них в существующих кошельках.
- Кошельков два: «Наличные / Cash» (иконка `USD banknote`) и «Кредитная
  карта / Credit card» (иконка `Visa card`), оба с нулевым балансом. Валюта
  — по языку посева: `RUB` для русского, `USD` для остальных (обе есть в
  наборе). Решение владельца 2026-11-14; прежний сид навязывал чужие
  кошельки, эти два общие. Иконки уже есть в серверном наборе по умолчанию
  (wallet-api, `000037`), для них отдельной миграции не нужно. В сиде
  кошелёк — запись `accounts[]` с `currency_iso`, у которого может быть
  объект по языкам `{"ru": "RUB", "en": "USD"}`.
- Валюты и пары — ходовые для русскоязычного пользователя; флаги в
  `res/drawable` уже есть для части, остальные добавляются.
- Флаги прежнего сида без валюты в наборе (ALL, ARS, BAM, CLP, HRK, KES,
  TZS) остаются иконками — секция `flag_icons`, прежние имена: человек
  заводит такую валюту сам и берёт готовый флаг.
- Курсов нет: курс на дату сборки через год хуже отсутствующего. Без входа
  эквивалент считается по курсам, введённым вручную, как для любой пары без
  курсов.
- Иконки категорий — только общие (без `Alfa bank`, `Tinkoff`, `VTB`,
  `Wirex`, `Ремонт чистовые`).

Утверждённый список категорий (задача 1.1, 2026-11-14; у каждой — пара
`{ru, en}`, см. D10): Продукты, Кафе и
рестораны, Транспорт, Такси, Топливо, Автосервис (en «Vehicle Maintenance»),
Жильё, Коммунальные
услуги, Связь и интернет, Здоровье, Аптека, Одежда и обувь, Красота и уход,
Дети, Домашние животные, Развлечения, Путешествия, Подарки, Образование,
Спорт, Подписки, Дом и быт, Прочие расходы, Зарплата, Подработка, Проценты,
Прочие доходы. Валюты: RUB, USD, EUR, GBP, CNY, KZT, BYN, UAH, GEL, AMD,
TRY, RSD, PLN, THB, AED, BTC, LTC (у двух последних 8 знаков, иконки
`flag_btc`/`flag_ltc`; Android их кодов не знает, название при посеве —
запасное из `seed.json`). Пары: каждая фиатная валюта к USD и к EUR, плюс
EURUSD; для криптовалют — `BTCUSD`, `BTCEUR`, `LTCUSD`, `LTCEUR` (цена монеты).
Всего 27 категорий и 2 системные, 17 валют, 31 пара.

### D3. Метка `from_seed` (БД v88)

Колонка `from_seed INTEGER NOT NULL DEFAULT 0` у `account`, `currency`,
`currency_pair`. Сид ставит 1. `WalletDbCRUD` сбрасывает в 0 при правке
имени, иконки, кода, символа. Апгрейд добавляет колонку с 0, так что
существующие базы, включая базу с прежним личным сидом, ничего «из набора»
не имеют. Колонка не входит в push: сборщики `collect*` перечисляют
колонки явно, новую не добавляем.

*Альтернатива:* узнавать строку набора по имени из `seed.json`. Отвергнута:
переименованная пользователем строка с именем из набора неотличима от
нетронутой, а набор меняется между версиями.

### D4. Признак «идёт подключение»

`AppSettings.ledgerConnectionPending`: ставится в начале прохода, если есть
сессия и `SyncEngine.hasSyncedRows(db) == false`; снимается после прохода,
где отправка прошла без ошибки, или после «Удалить с телефона».
`hasSyncedRows` один не подходит: после частично принятой загрузки
заменённые строки уже `dirty = 0`, и следующий проход перестал бы быть
подключением.

### D5. Порядок прохода при подключении

```
 refresh -> pull (with key adoption) -> connection step -> push -> purge
                                             |
                                             +-- question pending -> outcome «ждёт решения», no push
```

Загрузка первой — иначе push отправил бы набор до того, как телефон узнал,
пуст ли кошелёк. Обычный проход не меняется.

### D6. Принятие по ключу на загрузке

Только при подключении: при вставке пришедшей `currency` / `currency_pair` /
`account`, если локальная строка с тем же ключом есть и `dirty <> 0`,
вместо вставки обновляем эту локальную строку — `uuid` и поля серверной,
`dirty = 0`, `from_seed = 0`. Связи на телефоне идут по `_id`, поэтому
операции, `account_operating` и пары переклеивать не нужно. Ключ счёта
нормализуется как в серверном `uq_account_name`: `lower`, «Ё» → «Е».
`account_operating` кошелька приходит отдельной строкой с тем же uuid,
что и счёт, и после принятия счёта ложится на него обычным upsert.

*Альтернатива:* полагаться на 409 `duplicate_name` при push. Отвергнута: при
загрузке до отправки столкновение случается раньше push, а для валют и пар
сервер такого ответа не даёт.

### D7. Шаг подключения после загрузки

«Кошелёк не пуст» — на телефоне есть живой счёт с `dirty = 0`, то есть
пришедший из потока кошелька или принятый по ключу.

- Не пуст: удалить строки с `from_seed = 1`, `dirty <> 0`, без `system_kind`,
  без ссылок (операции, повторяющиеся операции, пары, валюта кошелька).
  Нетронутый кошелёк набора (без операций, не актив и не заём) удаляется
  вместе со своей строкой `account_operating` — иначе человек с живым
  кошельком на сервере получал бы две лишние пустые карточки; кошелёк
  с операциями остаётся. Валюта кошелька набора удаляется следом, если
  больше ничем не используется. Удаление
  жёсткое: на сервере этих строк нет, tombstone не нужен. Затем, если
  остались неотправленные операции, — вопрос (D8), иначе push.
- Пуст: ничего не удалять, push.

### D8. Вопрос и его исход

Диалог показывает главный экран, если признак «ждёт решения» стоит
(`AppSettings`), — при каждом открытии, пока решения нет. Число N — живые
операции с `dirty <> 0`, склонение через plurals. «Перенести» снимает
признак ожидания и запускает проход: шаг подключения видит, что решение
есть, и идёт в push. «Удалить с телефона» после подтверждения в одной
транзакции удаляет операции и счета/валюты/пары с `dirty <> 0` (свои
иконки не трогает), снимает оба признака; следующий проход обычный.

### D9. Без сети и при отказе сервера

Загрузка не удалась — шаг подключения и push не выполняются, признак
подключения остаётся; принятые на предыдущих страницах строки остаются
принятыми (страница применяется транзакцией). Без входа ничего не меняется:
проход заканчивается «нет сессии», набор живёт на телефоне сколько угодно.

### D10. Язык набора и названия валют

- В `seed.json` у категории вместо `name` — `names: {"ru": …, "en": …}`.
  Язык посева: `Locale.getDefault().getLanguage()`, `ru` → русский, иначе
  английский. Двух файлов не заводим: пара имён у одной строки не даёт
  языкам разойтись по составу.
- Системные `Transfer`/`Transfer commission` — одно имя (D2); их
  локализованный показ по `system_kind` — в change `android-i18n`.
- Валюты набора: `name` в сиде — запасной; при посеве название берётся из
  `java.util.Currency.getInstance(iso).getDisplayName(locale)`, если код
  Android известен.
- Показ общей валюты (`is_shared = 1`): одна функция «показываемое имя
  валюты» в слое данных — `getDisplayName(текущий язык)`, иначе хранимое
  `name`. Ею пользуются список «Валюты», пикеры и форма. Своя валюта — всегда
  хранимое `name`, чтобы не затереть «Доллары нал» именем по коду.
- Иконки не локализуются: их имя — ключ сопоставления с сервером
  (`icon-sync`, заместитель по имени).

*Альтернатива:* хранить переводы названий общих валют на сервере.
Отвергнута: Android знает названия валют по ISO на всех языках, а правка
сервера не нужна.

## Risks / Trade-offs

- [Android на разных версиях даёт разное написание и регистр названий
  («евро» против «Евро»)] → допустимо; в сценариях тестов — значения,
  которые даёт Robolectric.

- [Пустой старт без кошельков — экраны раньше не видели базу без кошельков]
  → ручная проверка чистой установки: главный экран, ввод операции,
  создание первого кошелька.
- [Категории набора с другим именем, чем в живом кошельке («Кафе и
  рестораны» против «Кафе»), с операциями останутся дублями] → объединение
  категорий на вебе; без операций нетронутые удаляются (D7).
- [Без общих валют на сервере валюты набора уходят в кошелёк как свои] →
  допустимо; общий справочник наполняет администратор.
- [Признак «ждёт решения» блокирует push бессрочно, если пользователь не
  отвечает] → диалог при каждом открытии главного экрана; данные остаются
  на телефоне.
- [Принятие по имени счёта склеит разные по смыслу одноимённые счета] → то
  же правило уже действует для `duplicate_name` на сервере.

## Migration Plan

- БД v88: колонка `from_seed` = 0 у трёх таблиц; никакие строки не
  удаляются и не меняются.
- Существующие установки наборов не получают (сид только в `onCreate` и
  пересеве). Прежний личный `seed.json` удаляется из репозитория: данные
  автора лежат в его кошельке на сервере.
- Откат — предыдущая версия APK; колонка `from_seed` старой версии не
  мешает.
