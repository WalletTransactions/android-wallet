# Design

## Context

Архивация — галочка «Заархивированный» на экране «Кошелёк» (`AccountItemActivity`),
сохраняется кнопкой «Сохранить» одной транзакцией вместе с именем, валютой и
признаком актива. Похожая готовая механика — «Переоценка» актива (`RevaluationDialog`,
`WalletDbCRUD.WriteRevaluation`): дата через `CalendarPicker`, проводка на `23:59`,
округление до точности валюты, после записи `markDataChanged()` и синк в фоне.

## Решения

- **D1. Опечатка в задаче.** «В случае нулевого остатка» читается как «ненулевого»:
  при нулевом остатке списывать нечего, архивация идёт как раньше, диалога нет.
- **D2. Какой остаток списывается.** Итоговый — по всем живым проводкам кошелька,
  независимо от выбранной даты. Цель — чтобы после архивации кошелёк был в нуле, даже
  если после выбранной даты есть операции. Цена: на выбранную дату в истории остаток
  может временно уйти в минус. (Предложено в разборе задачи 2026-11-07, владелец
  перевёл задачу в работу без возражений.)
- **D3. Направление.** Остаток > 0 — «кошелёк → категория» на остаток (расход);
  < 0 — «категория → кошелёк» на |остаток| (доход, закрывает минус). Сумма — в валюте
  кошелька, у категории валюты нет — конвертации нет. Остаток округляется до
  `precision` валюты (HALF_UP); после округления 0 — как нулевой остаток (D1).
- **D4. Активы не трогаем.** Для кошелька, отмеченного как капитальный актив (до или
  после сохранения), диалог не показывается: «списать на категорию» по смыслу —
  продажа или обнуление оценки, для этого есть «Переоценка». Расширить можно
  отдельной задачей. (Также из разбора задачи.)
- **D5. Когда показывается.** Только кошелёк (`AccountOperatingItem`), не актив,
  галочка архива поставлена сейчас (`!originalArchived && checked`), остаток ≠ 0.
  Иначе «Сохранить» работает как раньше.
- **D6. Дата и время.** По умолчанию сегодня, выбирается `CalendarPicker`; время
  `23:59`, как у переоценки — проводка встаёт после всех операций того дня.
- **D7. Комментарий.** Строковый ресурс `archive_writeoff_comment`: «Архивация
  кошелька» / «Wallet archived» — на языке интерфейса, как комментарий переоценки.
- **D8. Категория.** По умолчанию не выбрана; «Списать и архивировать» без категории —
  подсказка «Выберите категорию» у поля. Выбор — `AccountPickerActivity` в режиме
  «только категории» с новым флагом `cHideSystem`: без «Перевода», «Комиссии» и
  «Переоценки» (архивные категории пикер уже прячет).
- **D9. Атомарность.** Проводка списания пишется внутри той же транзакции, что
  `UpdateAccount(... isArchive=true)`, валюта и признак актива: либо всё, либо ничего.
  Остаток пересчитывается внутри транзакции (а не берётся из диалога): если за время
  диалога пришёл синк, списывается актуальное число.
- **D10. Кнопки.** «Списать и архивировать» — проводка + сохранение; «Архивировать
  без списания» — сохранение как раньше; «Отмена» — ничего не пишется, экран остаётся
  открытым.
- **D11. После записи.** `reloadSingleton`, `PeriodFilterState.markDataChanged()`,
  `SyncRunner.runOnce` в фоне (как у переноса в актив), тост «Остаток списан».
- **D12. Только Android.** Web-архивация без диалога; паритет — отдельная задача.
  Снятие из архива проводку не откатывает — это обычная операция, удаляется вручную.

## Код

- `WalletDbLoader.LoadAccountBalance(db, id)` — итоговый остаток (D2).
- `WalletDbCRUD.WriteOffBalance(db, walletId, categoryId, day, precision, comment)` →
  `WriteOffResult {written, zero, failed}` — D2, D3, D6; работает внутри внешней
  транзакции (вложенная транзакция SQLite Android).
- `ArchiveWriteOffDialog` — разметка `dialog_archive_writeoff.xml` по образцу
  `dialog_revaluation.xml`; выбор категории — через активити (`onActivityResult`
  экрана «Кошелёк» передаёт выбор в диалог).
