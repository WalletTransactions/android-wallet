# Proposal

Задача: [android-wallet#28](https://github.com/WalletTransactions/android-wallet/issues/28) — «архивация кошелька».

## Why

Архив кошелька — признак только для интерфейса: архивный кошелёк пропадает из выбора
счёта при вводе операции, но его остаток остаётся в итогах, в карточке состояния
денег и в отчётах. Если заархивировать кошелёк, на котором «висит» остаток
(потерянные наличные, неучтённые мелкие траты), эти деньги навсегда остаются в
капитале, а поправить их обычной операцией неудобно — кошелька нет в пикерах.

## What Changes

- При архивации кошелька с ненулевым остатком экран «Кошелёк» предлагает списать
  остаток одной проводкой на выбранную пользователем категорию, на выбранную дату,
  с комментарием «Архивация кошелька».
- Диалог: остаток, категория, дата, кнопки «Списать и архивировать», «Архивировать
  без списания», «Отмена».
- Проводка и архив пишутся одной транзакцией; после записи — обычный синк.
- Выбор категории для списания не предлагает системные категории («Перевод»,
  «Комиссия», «Переоценка»).
- Сервер, web и схема БД не меняются.

«Что сделать» из задачи → пункты tasks.md:
- «предлагать списать оставшееся средство на выбранную категорию» → 1.2, 2.1–2.3;
- «проводка с выбранным пользователем числом» → 2.2 (дата в диалоге), 1.1;
- «с комментарием архивация кошелька» → 1.1, 2.4.

## Capabilities

### New Capabilities
- `wallet-archive-writeoff`: списание остатка кошелька при архивации.

### Modified Capabilities
- нет.

## Impact

- Android: `AccountItemActivity`, новый `ArchiveWriteOffDialog` и его разметка,
  `WalletDbCRUD` (запись списания), `WalletDbLoader` (итоговый остаток),
  `AccountPickerActivity` (режим без системных категорий), строки ru/en.
