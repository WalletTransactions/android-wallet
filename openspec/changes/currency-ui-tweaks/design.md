# Design

## Context

- Локальные `currency` и `currency_pair` не знают, общая строка или своя:
  `ledger_id` из pull сейчас отбрасывается (`SyncEngine.applyCurrency`,
  `applyCurrencyPair`). Сервер молча пропускает push общей строки
  (`sync_push_foreign_row_skipped`). Значит, если «удалить» общую пару на
  телефоне, она исчезнет локально и останется на сервере, то есть данные
  тихо разойдутся.
- На всех синк-таблицах висит `trg_<table>_dirty`: любой `UPDATE`, который
  сам не меняет `dirty`, ставит `dirty = 1`. Pull пишет `dirty = 0` явно.
- `CurrencyPickerActivity` сейчас только возвращает выбор. Его открывает
  диалог «Новая валютная пара». Правка валюты (✎ → `CurrencyFormActivity`)
  уже есть.
- Пикеров эквивалента два: `BaseTabActivity.onPickCurrencyEq` (валюты живых
  кошельков, иначе все) и `SettingsActivity.onPickMainCurrency` (все).

## Goals / Non-Goals

**Goals:** см. specs `currency-pairs`, `currency-directory`.

**Non-Goals:**
- REST `/api/currency-pairs*` и `/api/currencies*` телефоном не
  используются: вся запись телефона идёт через синк. REST валют — для веба
  (`wallet-web: currency-ui-tweaks`).
- Правило удаления валюты (`IsCurrencyInUse`) не меняется. Сервер повторяет
  его в REST.

## Decisions

### D1. `is_shared` хранится локально и берётся из `ledger_id` в pull
Колонки `currency.is_shared` и `currency_pair.is_shared` (`INTEGER NOT NULL
DEFAULT 0`). `applyCurrency`/`applyCurrencyPair` пишут `is_shared =
row.isNull("ledger_id") ? 1 : 0`. Строки, созданные на телефоне, остаются
своими (`0`).
Альтернатива — определять общую строку по потоку pull (`reference`/`ledger`).
Она эквивалентна, но протаскивать поток в `apply*` сложнее, чем читать поле
строки.

### D2. Заполнение `is_shared` у уже скачанных строк — повторный pull потока `reference`
Миграция v85 только добавляет колонки, без `UPDATE`: любой `UPDATE` поднял
бы `dirty` через триггер и отправил бы весь справочник в push. После
миграции курсор `reference` сбрасывается в 0 (`AppSettings.setReferenceSyncSeq`,
вызывается из `onUpgrade`, у `WalletDbHelper` есть `Context`). Ближайший
синк перекачивает общие строки, и они получают `is_shared = 1`.
Альтернатива — сравнить `uuid` с чем-то известным. Её отвергли: на
телефоне нет другого источника «общности».

### D3. Удаление пары — мягкое, вместе с курсами, одной транзакцией
`WalletDbCRUD.DeleteCurrencyPair(db, pairId)`: `deleted_at` у пары и у всех
её живых `currency_pair_rate`. `dirty` ставит триггер. Это тот же каскад,
что делает сервер в `DELETE /api/currency-pairs/{uuid}` (один seq на
группу). Push отправит и пару, и курсы. Перед удалением проверяется
`is_shared = 0`, и это не только скрытие кнопки в UI.
`currency_conversion`, ссылающаяся на пару, не трогается (сервер тоже её не
трогает). Эквивалент через эту пару становится неизвестным, это осознанное
следствие, о котором говорит текст подтверждения.

### D4. Список валют — тот же `CurrencyPickerActivity` с режимом просмотра
Новый экстра `ARG_BROWSE`. В режиме просмотра тап по строке открывает
`CurrencyFormActivity`, а не `setResult`. Заголовок «Валюты». Отдельную
активити не заводим: поиск, «+ Создать валюту» и адаптер одни и те же.
Подписи «общая» и «не в эквиваленте» добавляются в
`currency_picker_item_layout.xml` и видны в обоих режимах: при выборе
валюты для пары они тоже полезны.

### D5. Фильтрация пикеров эквивалента — в одном месте
Чистая функция (например, `EquivalentCurrencies.filter(List<Currency>
candidates, Currency current)`) реализует правило из spec: оставить
валюты с флагом, добавить текущую, при пустом результате вернуть исходный
список. Её зовут оба пикера. Отдельный класс нужен ради юнит-теста без
Activity.

### D6. Совместимость с сервером
Push всегда шлёт `show_in_equivalent`. Старый сервер (без миграции wallet-api
000026) лишний ключ игнорирует, потому что строит SQL по своему списку
колонок. Флаг тогда живёт только на телефоне. Pull без ключа не трогает
локальное значение (`row.has(...)`), чтобы старый сервер не сбрасывал флаг.

### D7. Общая валюта в форме только для чтения
Сейчас форма даёт править и удалять общую валюту. Сервер такой push
молча пропускает, и данные на телефоне расходятся с сервером. Теперь, когда
есть `is_shared` (D1), `CurrencyFormActivity` для общей валюты делает поля
и переключатель неактивными, скрывает «Сохранить» и «Удалить» и показывает
подпись. Это то же правило, по которому REST wallet-api отвечает `404` на
правку общей валюты, поэтому веб и телефон ведут себя одинаково.
Альтернатива — копировать общую валюту в свою при правке. Её отвергли:
появилась бы своя валюта с тем же кодом, а форма такое запрещает
(«Валюта с таким кодом уже есть»).

### D8. Код валюты, входящей в пару, не меняется
Символ пары — склейка ISO-кодов, и телефон находит пару по символу
(`getCurrencyPairIdBySymbol`, запись курсов). Смена кода оставила бы пару
со старым символом. `onSave` при изменённом коде проверяет живые пары с
этой валютой (`WalletDbCRUD`, рядом с `IsCurrencyInUse`) и ставит ошибку у
поля. Это то же правило, что `409 currency_in_pair` в REST wallet-api
(там же, в design D6, записана альтернатива с пересчётом символов).

### D9. Правки с веба доходят сами
Валюты, изменённые через REST, приходят в поток леджера обычным pull.
`SyncEngine` после применения валют уже вызывает
`Singleton.reloadCurrencyList`, так что нужна только проверка, а не новый
код.

### D10. «+» убирается только с таба «Кошельки»
Счета заводятся в двух местах с одним и тем же диалогом «Кошелёк /
Категория»: в шапке таба «Кошельки» (`AccountActivity.onAddAccount`) и в
справочнике (`AccountPickerActivity`, режим `cCatalogMode`, строка
`btnAddAccountRow`). Убирается первое: таб «Кошельки» — это отчёт по
остаткам, а справочник — место, где счета правят и снимают с архива. Из
`AccountActivity` уходят кнопка `btnAddAccount`, `onAddAccount` и обработка
`REQUEST_ADD_WALLET`/`REQUEST_ADD_CATEGORY` в `onActivityResult`. Шапка
остаётся общей с другими табами (`view_tab_title` + `view_tab_actions`).
Сами `AddWalletActivity`/`AddCategoryActivity` не меняются.

### D11. «Готово» под клавиатурой: две причины
1. У `MultiPickerActivity` в манифесте нет `windowSoftInputMode`, поэтому
   система сама выбирает между pan и resize. На деле она сдвигает окно
   (pan), и нижняя кнопка уходит под клавиатуру. Лечится явным
   `adjustResize`: `ListView` с `layout_weight=1` укорачивается, `btnDone`
   встаёт над клавиатурой. `targetSdk` 34, принудительного edge-to-edge
   нет, `adjustResize` работает без обработки insets.
2. `AppSettings.applyPickerKeyboard` вызывает
   `setSoftInputMode(SOFT_INPUT_STATE_ALWAYS_VISIBLE)`. Это полная замена
   режима, в том числе битов adjust, так что `adjustResize` из манифеста
   затёрся бы, как только включена настройка «клавиатура на экранах выбора».
   Функция меняет только биты state и сохраняет текущие биты
   `SOFT_INPUT_MASK_ADJUST`.

`adjustResize` ставится и у `AccountPickerActivity`: у него тот же
`applyPickerKeyboard`, а в режиме справочника внизу есть строка «+
Добавить», которую клавиатура закрывает так же.

Enter: у `searchInput` ставится `imeOptions="actionDone"`, а
`OnEditorActionListener` на `IME_ACTION_DONE` или на `KEYCODE_ENTER`
(физическая клавиатура присылает `actionId = IME_NULL` с `KeyEvent`)
вызывает тот же `onDone`. Повторный вызов на `ACTION_UP` после `ACTION_DOWN`
отсекается проверкой `KeyEvent.ACTION_DOWN`. `onDone` уже собирает выбор по
`mAllItems`, а не по видимым строкам, поэтому скрытые поиском отмеченные
счета не теряются.

## Поведение без сети и при отказе сервера

- Удаление пары и правка флага полностью локальные и сразу видны в UI.
  Отправка идёт обычным push'ем при следующем синке.
- Если push отвергнут (`409`/`400`), строки остаются `dirty` и уходят
  повторно (действующее поведение `sync-run`).
- До первого синка после обновления `is_shared` у всех строк 0: удаление
  общей пары локально возможно (D2). Сервер такой tombstone пропустит, а
  повторный pull `reference` вернёт пару (`deleted_at` с сервера `NULL`).
  Окно короткое и самоисправляющееся.

## Правки в других сервисах

- **wallet-api** (`wallet-api: currency-ui-tweaks`): колонка
  `currency.show_in_equivalent`, необязательный ключ в push, REST валют для
  веба с теми же правилами (D7, D8).
- **wallet-ai, google-auth, wallet-gateway**: без правок.

## Risks / Trade-offs

- [Повторный pull `reference` тянет все общие иконки и курсы] → это
  разовая операция. При реализации проверить, перекачивает ли
  `applyIcon` содержимое блоба, если `content_sha256` не изменился. Если
  перекачивает, пропускать скачивание при совпадающем хэше (задача 2.4). На
  медленной сети первый синк после обновления дольше обычного.
- [Пользователь скрыл текущую валюту эквивалента и удивился, что она
  осталась] → по spec текущая видна отмеченной; это лучше, чем молча
  пересчитать все отчёты в другую валюту.
