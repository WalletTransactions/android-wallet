## Requirements

### Requirement: Папка экспорта без разрешений
Экспорт базы и JSON SHALL записывать файл в папку приложения
`Android/data/<пакет>/files/Download` на всех поддерживаемых версиях Android
(с 8.1). Экспорт MUST NOT требовать разрешений на доступ к памяти. «Поделиться»
SHALL отдавать последний экспортированный файл через FileProvider.

#### Scenario: Android 8–9
- **WHEN** на Android 9 пользователь нажал «Экспортировать БД»
- **THEN** файл `wallet_android_<время>.db` записан в папку приложения, без запроса разрешений и без ошибки

#### Scenario: Android 10 и новее
- **WHEN** на Android 14 пользователь нажал «Экспортировать в JSON»
- **THEN** файл `wallet_export_<время>.json` записан в ту же папку приложения, как и раньше

#### Scenario: Поделиться
- **WHEN** после экспорта пользователь нажал «Поделиться»
- **THEN** открывается системный выбор приложения с этим файлом

### Requirement: Экран «Экспорт базы»
Пункт «Экспорт базы» в разделе «ДАННЫЕ» экрана «Настройки» SHALL открывать
экран «Экспорт базы» с пояснением и кнопками «Экспортировать БД»,
«Экспортировать в JSON» и «Поделиться». «Поделиться» SHALL быть неактивной,
пока на этом экране не завершился успешный экспорт. Экспорт идёт в фоне:
виден индикатор, в статусе «Экспортирование…», кнопка запущенного экспорта
и «Поделиться» неактивны (при экспорте в JSON неактивны обе кнопки
экспорта).

#### Scenario: Открытие экрана
- **WHEN** пользователь открывает «Настройки» → «Экспорт базы»
- **THEN** видны «Экспортировать БД», «Экспортировать в JSON» и неактивная «Поделиться»

### Requirement: Экспорт файла базы
«Экспортировать БД» SHALL копировать файл базы `wallet.db` байт в байт в
файл `wallet_android_<yyyy-MM-dd_HHmmss>.db` папки экспорта. При успехе
в статусе «Готово!» и полный путь файла, всплывает «Экспорт успешно
завершен», «Поделиться» становится активной. Нет файла базы — ошибка
«Ошибка: Файл базы данных не найден».

#### Scenario: Успешный экспорт БД
- **WHEN** 11 ноября 2026 в 14:05:09 пользователь нажал «Экспортировать БД»
- **THEN** записан `wallet_android_2026-11-11_140509.db`, в статусе «Готово!» и путь к нему, всплывает «Экспорт успешно завершен»

### Requirement: Экспорт в JSON
«Экспортировать в JSON» SHALL записывать в папку экспорта файл
`wallet_export_<yyyy-MM-dd_HHmmss>.json` в UTF-8 с отступом 2. Корень —
объект с ключами `_comment` (описание формата разделов), `accounts`,
`currency_pairs`, `rates`, `operations`; каждый раздел SHALL
присутствовать, даже пустой. При успехе в статусе «Готово!» и путь,
всплывает «Экспорт в JSON завершён», «Поделиться» становится активной.

#### Scenario: Пустая база
- **WHEN** на телефоне нет ни счетов, ни операций, пользователь нажал «Экспортировать в JSON»
- **THEN** файл содержит `_comment` и пустые массивы `accounts`, `currency_pairs`, `rates`, `operations`

### Requirement: Содержимое JSON-экспорта
JSON SHALL содержать только живые (не помеченные удалёнными) строки.
`accounts` — счета в порядке создания: `name`, `comment`, `icon` (имя
иконки, `unknown`, если иконки нет) и для кошелька `currency` с `name`,
`iso`, `icon` (пустая строка без иконки); у категории `currency` нет.
`currency_pairs` — `symbol`, `base`, `quote` (коды валют). `rates` —
`symbol`, `date` (`YYYY-MM-DD`), `rate`, по символу и дате. `operations` —
в порядке ввода: `date` (только день, без времени), `from`, `to` (имена
счетов), `amount`, `comment` (пустая строка без комментария).

#### Scenario: Кошелёк и категория
- **WHEN** есть кошелёк «Наличные евро» в EUR с иконкой `Wallet` и категория «Кафе» с иконкой `Cafe`
- **THEN** в `accounts` у «Наличные евро» объект `currency` с `"iso": "EUR"`, у «Кафе» ключа `currency` нет

#### Scenario: Удалённая операция
- **WHEN** операция удалена на телефоне
- **THEN** в `operations` её нет

### Requirement: Перевод и комиссия в JSON-экспорте
Связанные проводки SHALL выгружаться одной операцией, а не по строкам:
вторая часть разновалютного перевода — как `leg.amount`, при этом `to` —
настоящий получатель, а не категория-мост `Transfer`; комиссия — как
`commission` с `amount`, `category` (имя категории комиссии) и `from`:
`dest`, если комиссия списана со счёта получателя, иначе `source`.
Связанные проводки отдельными элементами `operations` не выгружаются.

#### Scenario: Валютный перевод с комиссией
- **WHEN** на телефоне перевод 5000 с «Карта» на «Карта USD» (65.4) с комиссией 50 с «Карта»
- **THEN** в `operations` один элемент: `"from": "Карта"`, `"to": "Карта USD"`, `"amount": 5000`, `"leg": {"amount": 65.4}`, `"commission": {"amount": 50, "from": "source", "category": "Transfer commission"}`

### Requirement: JSON-экспорт читается импортом
Файл JSON-экспорта SHALL приниматься кнопкой «Импортировать из JSON»
(`data-import`) без правок: счета, пары, курсы и операции с переводами и
комиссиями восстанавливаются в той же структуре.

#### Scenario: Перенос на другой телефон
- **WHEN** файл `wallet_export_….json` с одного телефона импортирован на другом через «Импортировать из JSON»
- **THEN** на втором телефоне те же счета, пары, курсы и операции, перевод с комиссией — одной операцией

### Requirement: Ошибка экспорта
Ошибка экспорта SHALL показываться в статусе и всплывающим сообщением как
«Ошибка: <причина>»; индикатор скрывается, кнопки экспорта снова активны,
«Поделиться» остаётся неактивной до следующего успешного экспорта.

#### Scenario: Нет папки экспорта
- **WHEN** папку экспорта не удалось создать
- **THEN** показано «Ошибка: Не удалось создать папку Downloads», файл не записан

### Requirement: Поделиться последним экспортом
«Поделиться» SHALL открывать системный выбор приложения для последнего
файла, экспортированного на этом экране: для JSON — с заголовком
«Поделиться JSON-экспортом» и типом `application/json`, для БД — с
заголовком «Поделиться файлом БД» и типом `application/octet-stream`.
Файла больше нет — «Сначала экспортируйте БД». Возврат из выбора не
запирает приложение кодом доступа.

#### Scenario: Поделиться JSON
- **WHEN** после «Экспортировать в JSON» пользователь нажал «Поделиться»
- **THEN** открыт выбор «Поделиться JSON-экспортом» с этим `.json`
