# android-wallet — «Посчитай и сбереги»

Android-приложение для учёта личных финансов: кошельки в разных валютах,
доходы и расходы по категориям, переводы, повторяющиеся операции, отчёты
и курсы валют. Работает офлайн на локальной SQLite; при желании
синхронизируется с собственным сервером WalletTransactions.

## Возможности

- **Операции** — доходы, расходы, переводы между кошельками (в т.ч.
  валютные, с комиссией), фильтр по периоду, категориям и кошелькам.
- **Кошельки** — счета в любых валютах, остатки и эквивалент в выбранной
  валюте.
- **Отчёты** — доходы и расходы по категориям за период.
- **Повторяющиеся операции** — правила с расписанием, включаются и
  выключаются одним переключателем.
- **Курсы валют** — валютные пары, история курсов и график; загрузка из
  Frankfurter (ECB), ЦБ РФ и Yahoo Finance.
- **Иконки** — свои иконки категорий и кошельков с кадрированием.
- **Импорт / экспорт** — JSON-формат всей базы (тот же, что понимает импорт
  из Money Lover): контрагенты (`counterparties`), счета с блоками `debt`
  (долговой кошелёк: контрагент, срок, комментарий) и `asset` (капитальный
  актив: `real_estate`/`vehicle`/`other`), метка `"system": "revaluation"` у
  категории «Переоценка», валютные пары, курсы, операции с переводами и
  комиссиями. Все разделы необязательны; описание формата — в `_comment`
  экспортированного файла и в диалоге «Формат» экрана импорта.
- **Синхронизация** — вход через Google (Credential Manager), push/pull
  изменений с сервером, фоновое автоподключение через WorkManager.
- **ИИ** — трата своими словами («вчера такси 450 с тинькоффа»): текстом,
  голосом или через «Поделиться» из другого приложения; разбирает сервер
  (wallet-ai), записывает пользователь. См. «Экран «ИИ»» ниже.
- **Импорт выписки** — PDF или CSV из банковского приложения («Поделиться»
  или выбор файла): сервер разбирает строки и предлагает категории, телефон
  проверяет дубли, пользователь записывает по одной или «готовые» пачкой.
  См. «Импорт выписки» ниже.

Нижняя навигация: **Операции · Кошельки · Отчёт · Ещё**.

## Сборка и запуск

Нужны JDK 17 и Android SDK (platform 34, build-tools 30.0.3). Путь к SDK —
в `local.properties` (`sdk.dir=...`), файл в git не хранится.

```bash
./gradlew assembleDebug             # оба варианта: app/build/outputs/apk/{prod,qa}/debug/
./deploy-debug.sh [serial]          # собрать и поставить prod на устройство через adb
FLAVOR=qa ./deploy-debug.sh         # то же для qa; FLAVOR=all — оба
```

### Варианты: prod и qa

Два приложения рядом на одном телефоне, у каждого своя база, настройки и вход
(openspec `android-flavors`):

| Вариант | Пакет | Название | Сервер по умолчанию |
|---|---|---|---|
| `prod` | `com.example.wallettransactions` | «Посчитай и сбереги» | `http://localhost:8090/` |
| `qa` | `com.example.wallettransactions.qa` | «QA Посчитай и сбереги» (оранжевая иконка с плашкой «QA») | `http://localhost:8091/` (test-контур) |

LAN-адрес хоста вводится в «Ещё» → «Интеграции» в каждом приложении. Вход
Google в `qa` работает, только если в Google Cloud зарегистрирован Android
OAuth client для `com.example.wallettransactions.qa` с SHA-1 debug-ключа хоста
(см. `openspec/changes/android-flavors/design.md`).

`versionCode` растёт автоматически при каждой сборке (`app/version.properties`),
`versionName` — `1.0.<code>`; версия и время сборки видны в «Настройки → О приложении».

## Релизы

Тег `v*` собирает APK и публикует GitHub Release с ним
(`.github/workflows/release.yml`):

```bash
git tag v1.1.0 && git push origin v1.1.0
```

Или вручную: Actions → Release → Run workflow с именем тега. Каждый push в
`main` и pull request тоже собирают debug-APK — он лежит артефактом прогона CI
14 дней.

Подпись: без секретов `RELEASE_*` APK подписан временным ключом раннера и
ставится только на устройство без приложения — поверх сборки с телефона или
прошлого релиза не встанет. Чтобы релизы обновляли друг друга, нужен отдельный
постоянный ключ релизов в секретах репозитория (список — в начале
`release.yml`). Ключ хоста и ключ Google Play туда не кладутся.

## Синхронизация с сервером

Приложение полностью работает без сервера. Для синхронизации: «Ещё →
Синхронизация» — указать адрес сервера (по умолчанию `http://localhost:8090/`)
и связать аккаунт через Google.

Поток: `POST /auth/nonce` → Credential Manager (Google ID token) →
`POST /auth/google/mobile` → пара access/refresh-токенов → `POST /sync/push` /
`pull`. На текущем этапе сервер доступен только в LAN и без TLS, поэтому
в манифесте включён `usesCleartextTraffic`.

Серверная часть (wallet-api, google-auth и др.) — в соседних репозиториях
организации [WalletTransactions](https://github.com/WalletTransactions).

## Экран «ИИ»

«Ещё → ИИ» — трата своими словами через сервис wallet-ai (контракт —
`wallet-ai/openapi.yaml`, `/api/ai/*` через гейтвей). Пункт активен, только
если есть вход в аккаунт и сервер отвечает, что ИИ включён
(`GET /api/ai/status`); иначе под ним причина.

1. Текст вводится в поле (до 500 символов), надиктовывается кнопкой микрофона
   или приходит через «Поделиться» (`text/plain`) из другого приложения —
   например, сообщение банка из Viber. Разбор сам не запускается: текст можно
   поправить.
2. «Разобрать» сначала синхронизирует телефон с сервером (до 10 секунд), чтобы
   сервер выбирал кошелёк и категорию по тому же справочнику, что на телефоне.
   Не успел или не удался синк — разбор всё равно идёт, под полем
   предупреждение с причиной.
3. Ответ открывается в обычном окне «Новая операция»: сумма, кошелёк,
   категория, дата и комментарий из разбора, сверху — «Подсказка ИИ» (исходный
   текст и вопросы: «Какая категория?», «В тексте EUR, а кошелёк в RUB»).
   Варианты, которые предложил ИИ, стоят первыми в выборе кошелька и категории.
   Если выбранного сервером кошелька или категории нет на телефоне (не загружен,
   удалён, в архиве), окно сразу не открывается: экран «ИИ» показывает ошибку с
   деталями и кнопками «Синхронизировать и повторить» и «Открыть операцию».
4. «Сохранить» в окне записывает операцию в базу телефона, как ручной ввод; на
   сервер её отвезёт синк. Записать можно и без сети, если разбор уже получен.
   Закрыли окно без сохранения — «Открыть снова» вернёт тот же разбор без
   нового запроса к ИИ.

ИИ недоступен или не понял текст — «Заполнить вручную» открывает обычный экран
новой операции с текстом в комментарии.

Приватность: текст траты уходит на свой сервер (wallet-ai), в logcat
приложения он не пишется. Голос распознаёт системный сервис Android; если на
телефоне нет офлайн-пакета русского языка, запись может уйти в облако
распознавания (обычно Google).

## Импорт выписки

Экран «Выписка»: «Ещё → ИИ → Загрузить выписку» или «Поделиться» файлом из
банковского приложения («Выписка в Кошелёк»). Разбирает сервис wallet-ai
(`/api/ai/imports*`, контракт — `wallet-ai/openapi.yaml`), записывает телефон.

1. Файл — PDF с текстом, CSV или TXT до 5 МБ — и кошелёк выписки. «Загрузить»
   сначала синхронизирует телефон (кошелёк, созданный на телефоне, иначе
   серверу неизвестен), затем отправляет файл. Скан без текста, файл без
   операций, большой файл — причина под формой, файл и кошелёк остаются.
2. Разбор идёт на сервере и занимает минуты. Экран показывает «Разбираю
   выписку: 2 из 6», пока открыт; с него можно уйти — при следующем открытии
   экран найдёт этот импорт сам. Уже идёт другой импорт — экран откроет его.
3. Готовый список: дата, сумма, продавец, категория (своя или «ИИ
   предлагает»), состояние строки — «Ждёт», «Нужна категория», «Проверить»
   (сумма или дата не сверились с текстом выписки), «Похоже, уже есть: 12.10
   450,00 Такси» (такая операция уже есть на телефоне: тот же кошелёк и сумма,
   дата ±1 день), «Не для записи» (доходы и переводы), «Добавлена».
4. Тап по строке — обычное окно «Новая операция» со всеми полями строки:
   поправить сумму, категорию, вид и сохранить. «Записать готовые (N)» —
   одной кнопкой строки «Ждёт» с категорией, которая есть на телефоне.
5. Операция строки сохраняется с uuid = `row_id` строки, поэтому одна строка —
   одна операция: повторный тап открывает уже записанную на правку. Сервер
   получает отметку о записи и выбранную категорию — по ней он подставит
   категорию остальным строкам того же продавца. Без сети запись всё равно
   идёт в базу телефона, отметки уйдут при следующем открытии списка.

Повторная загрузка той же выписки не задвоит операции: все её расходы будут
«Похоже, уже есть». Записываются только расходы; доходы и переводы — позже,
вместе с сервером (`add-statement-transfers` в wallet-ai).
